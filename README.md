# scratch-studio

## 폴더

| 폴더 | 내용 |
| --- | --- |
| `docs/` | 커리큘럼 구성안(`scratch-curriculum-outline.md`), 기획서(`scratch-studio-spec.md`), 교안 틀(`scratch-lesson-template.md`), 본 사이트 기획서(`spec.md`), 강사용 안내서(`teacher-guides/`) |
| `styles/` | hi-fi 목업 |

| `app/` | 스크래치 전용 학습 화면 (목업 화면 15) |

## 학습 화면 실행

빌드 과정이 없는 정적 페이지다. 저장소 루트에서 다음을 실행하고 <http://localhost:8000/app/> 을 연다.

```
python app/serve.py
```

| 주소 옵션 | 뜻 | 기본값 |
| --- | --- | --- |
| `unit` | 단원 폴더 경로 | `../project/lv1/04-pirate-cannon` |
| `editor` | 에디터 iframe 주소 | `./editor-stub/index.html` |
| `exit` | "종료"와 "단원 목록으로"가 이동할 주소 | 이전 페이지 |
| `saveFail=1` | 첫 저장을 실패시켜 "저장 실패"와 "다시 시도"를 확인 | 끔 |

다른 단원 폴더를 열 때는 `unit`에 `unit.json`이 들어 있는 폴더를 준다. 진도는 폴더별로 따로 저장된다.

```
http://localhost:8000/app/?unit=../project/lv1/<단원 폴더>
```

## 배포 (Vercel)

교안을 보기 위한 배포다. 실제 수업용이 아니다.

주소: <https://scratch-studio-gray.vercel.app/> (`/app/`으로 연결된다)

- `main`에 푸시하면 Vercel이 자동으로 배포한다. 빌드 과정은 없다.
- `.vercelignore`로 `app/`과 `project/`만 올린다. `docs/`(강사용 안내서, 기획서), `tools/`, `styles/`는 올라가지 않는다.
- `vercel.json`: 첫 주소 `/`를 `/app/`으로 보내고, 모든 응답에 `noindex`를 붙인다.
- 배포 주소는 링크를 아는 누구나 볼 수 있다. 퀴즈 정답과 채점 규칙도 `unit.json`에 들어 있어 브라우저에서 보인다.
- 진도는 보는 사람의 브라우저에 저장된다. 서버가 없으므로 사람마다, 브라우저마다 따로 쌓인다.

### 버전 1: 결정할 점과 한계

**결정할 점**
- **교안 틀을 따를지**: 이야기가 3스텝, 퀴즈 4개가 스텝 사이사이에 있고, 완성 확인 스텝이 없으며, 확장 미션 뒤에 심화 도전(s26)이 한 스텝 더 있다. 교안 틀의 단원 흐름과 다르다.
- **퀴즈의 힌트와 해설**: 교안 틀과 기획서는 "틀려도 해설이나 틀린 문항을 보여 주지 않는다"고 정했는데, 1판 문항에는 힌트와 해설이 있다. 남길지 뺄지 정해야 한다.
- **퀴즈 형식**: 1판은 이전 형식(`"type": "quiz"`, `id`, `prompt`)이다. 가져오기 스크립트가 기획서 형식(`"kind": "quiz"`, `key`, `question`)만 받는다면 바꿔야 한다.
- **선택 스텝**: 꾸미기(s14, s15, s21)와 발사 수 세기(s23)가 채점 없는 선택 스텝으로 흐름 안에 있다. 교안 틀처럼 확장 미션으로 옮길지 정한다.
- **이야기 사진**: 외부 사진 5장(CC BY 3.0, 공공누리 등)을 쓴다. 출처 표기 방식과 사용 허락 범위를 확정해야 한다.

**한계**
- 교안 틀의 문장 규칙(굵게와 목록만)과 다르다. 표 6스텝, `##` 제목 3스텝, 코드 표기(`` ` ``) 21스텝이 있다.
- 블록 그림이 8개를 넘는 스텝이 있다: s19(11개), s26(9개).
- 미리보기 GIF가 없다. 채점이 없는 스텝이 13개라, 스텝의 상당수가 읽고 넘어가는 스텝이다.
- s18b 채점이 말풍선의 "명중"을 찾는다. 영어로 진행하면 교안대로 "Hit!"를 쓴 학생이 통과하지 못한다(값을 `{ "ko": "명중", "en": "Hit" }`로 바꿔야 한다).
- 강사용 안내서의 스텝 표에는 s23이 "자동 검사 있음"으로 되어 있지만 교안의 s23에는 검사가 없다.
- `tools/04-pirate-cannon/`의 생성 스크립트는 예전 판 기준이다. 다시 돌리면 지금 교안이 덮어써진다.

### 버전 2: 결정할 점과 한계

**결정할 점**
- **코드 퀴즈의 `blocks` 필드**: 코드를 읽고 고르는 문항이라 블록 그림 칸을 넣었다. 기획서 6장의 문항 필드(`key`, `question`, `options`, `answer`)에는 없으므로 기획서에 추가할지 정한다.
- **퀴즈 스텝 제목**: 기획서 형식에는 제목이 없어 화면에 "퀴즈"로만 나온다. 이야기 퀴즈와 코드 퀴즈를 구분할 제목을 둘지 정한다.
- **스프라이트 지정**: 교안 틀은 `@first`, `@any`를 쓰라고 하지만 스프라이트가 셋이라 이름(대포, 포탄, 과녁)으로 가리켰다. 기획서나 교안 틀에 예외로 적을지 정한다.
- **1판에서 가져올 것**: 이야기의 사실과 사진(천자총통, 타르탈리아, 블랙비어드), 5도 실험, 강사용 안내서 중 무엇을 2판에 옮길지 정한다.

**한계**
- 만들기 12스텝 × 약 6분, 합계 약 72분으로 잡았다. 교안 틀 기준(약 75분)에 맞는지는 수업에서 확인해야 한다.
- s14 채점이 말풍선의 "승리"를 찾는다. 영어로 진행해도 학생이 한국어 "승리!"를 입력해야 통과한다.
- GIF와 그림 속 글자("각도", "명중", "스페이스" 등)가 한국어로만 되어 있다.
- 교안 틀이 요구하는 `tests/`(정답·오답·다른 풀이 sb3)가 없다.
- 확장 미션은 교안 틀대로 미션 이름과 할 일만 적어 블록 그림이 없다. Lv.1 학생에게는 단서가 부족할 수 있다.
- 동적 검사로 구분할 수 없는 두 스텝은 정적 검사에 기댄다: s04(변수 만들기), s10(과녁이 처음부터 첫 자리에 있음).
- 강사용 안내서가 없다.

### 두 버전 공통

- **채점 엔진이 없다.** 채점 규칙은 좌표와 시간을 계산해 맞췄을 뿐 실제로 돌려 보지 않았다. 배포된 화면의 "확인"은 에디터 자리(stub)가 고른 결과를 돌려준다.
- **퀴즈 화면 동작이 문서와 다르다.** 교안 틀과 기획서는 틀린 문항을 알려 주지 않는다고 정했는데, 화면은 틀린 문항을 빨갛게 표시하고 힌트가 있으면 보여 준다. 화면을 문서에 맞출지, 문서를 고칠지 정해야 한다.
- **두 판의 `unitKey`가 같다**(`04-pirate-cannon`). 가져오기 스크립트로는 한쪽만 들어가므로, 비교가 끝나면 하나로 정해야 한다.
- **교안 위치와 과목 키**: 기획서는 `scratch-content/scratch-lv1/<단원>/`과 `tests/`를 쓰는데, 이 저장소는 `project/lv1/<단원>/`을 쓴다. 과목 키는 둘 다 `scratch-lv1`이다.
- **공개 범위**: 배포 주소는 누구나 열 수 있고, 퀴즈 정답과 채점 규칙이 `unit.json`에 들어 있어 브라우저에서 보인다.

## 아직 실제가 아닌 부분

- **에디터**: `app/editor-stub/`은 메시지 규약(기획서 4장)만 흉내 내는 자리다. 채점은 하지 않고 화면에서 고른 결과(통과, 실패, 오류, 응답 없음)를 돌려준다. 실제 에디터가 준비되면 `editor` 주소만 바꾼다.
- **서버**: `app/store.js`가 본 사이트의 API(기획서 8장)를 대신해 진도와 제출을 브라우저에 저장한다. 채점 규칙(`checks`)도 브라우저로 내려오므로 실제 사이트에서는 이 파일을 서버 호출로 바꿔야 한다.
- **미니퀴즈**: `unit.json`의 퀴즈 스텝을 그린다. 기획서 형식(`"kind": "quiz"`)과 이전 형식(`"type": "quiz"`)을 모두 읽는다. 모든 문항이 정답이어야 통과이고 다시 풀 수 있다. 정답이 브라우저로 내려오므로 실제 사이트에서는 서버가 판정해야 한다.
- **프로젝트 제출**: 사이트가 배치하는 기능이라 단원 끝에 제출 스텝을 붙인다.
