# 스크래치 학생용 교안 틀

Oct 14, 2026 · @Someone
최종 수정: 2026-10-16 — 해적선 대포(Lv.1-4) 교안을 기준으로 단원 흐름(이야기 1~3스텝, 개념 묶음마다 확인 퀴즈, 탐색·꾸미기 스텝, 목차), 퀴즈 동작(힌트와 해설), 입력 표, 소제목, 블록 이름 표기, 채점 규칙 쓰는 법을 고침

모든 학생용 교안은 같은 단원 흐름과 같은 만들기 스텝 틀(칸 5개, 고정 순서)을 쓴다. 이 틀은 스크래치 스튜디오의 교안 형식(`unit.json`의 스텝, 콘텐츠 블록 5종, `checks`, `chapters`)에 그대로 들어가도록 맞췄다.

## 단원 흐름

한 프로젝트는 아래 순서로 스텝을 놓는다. 사이트의 스텝 점 하나가 스텝 하나다. 가운데의 **개념 묶음**은 프로젝트에서 새로 배우는 개념(예: 방향과 변수, 조준, 발사, 명중)마다 한 번씩 되풀이한다.

| 순서 | 스텝 종류 | 들어가는 곳 | 채점 | 개수 | 하는 일 |
| --- | --- | --- | --- | --- | --- |
| 1 | 이야기 | `unit.json` 스텝 | 없음 | 1\~3 | 분야 이야기. 실제 사실과 그림·사진 |
| 2 | 오늘 만들 것 | `unit.json` 스텝 (마지막 이야기 스텝에 합쳐도 됨) | 없음 | 1 | 완성작 미리보기 GIF, 꼭 만들 것, 오늘 배울 개념 |
| 3 | 설계하기 (Lv.3만) | 사이트 입력 폼 | 없음 | 1 | 장면 → 등장하는 것 → 기억할 것 → 만드는 순서를 글로 정한다 |
| 4 | **개념 묶음** (되풀이) | | | | |
| 4-1 | 탐색 | `unit.json` 스텝 | 입력 표가 있으면 자동 | 묶음마다 0\~2 | 블록을 눌러 보거나 숫자를 바꿔 보며 결과를 관찰한다. 작품에 남지 않는다 |
| 4-2 | 만들기 | `unit.json` 스텝 | 자동 | 결과 수만큼 | 필수 구현을 한 조각씩 만든다 |
| 4-3 | 꾸미기 | `unit.json` 스텝 | 자동 | 묶음마다 0\~2 | 소리, 모양처럼 작품을 꾸미는 일. 다른 만들기와 같이 채점한다 |
| 4-4 | 확인 퀴즈 | `unit.json`의 `quiz` 스텝 | 퀴즈 | 묶음마다 1 (2\~3문항) | 그 묶음에서 쓴 코드와 개념을 묻는 객관식 |
| 5 | 완성 확인 | `unit.json` 스텝 | 자동 | 1 | 필수 구현 전체를 처음부터 실행해 확인. 기록표(채점 없음)를 함께 둘 수 있다 |
| 6 | 마무리 퀴즈 | `unit.json`의 `quiz` 스텝 | 퀴즈 | 1 (2\~3문항) | 단원 전체의 이유를 묻는 객관식 |
| 7 | 확장 미션 | `unit.json` 스텝 | 없음 (강사 확인) | 1 | 난이도별 미션 2\~3개 중 골라 하기 |
| 8 | 심화 도전 | `unit.json` 스텝 | 없음 (강사 확인) | 0\~1 | 확장 미션보다 한 단계 깊은 도전 하나 |
| 9 | 제출 | 사이트 프로젝트 제출 | 없음 | 1 | 제목, 배움 노트 2문항, 영상 링크(선택) |

**만들기 스텝 나누는 기준**: 실행해서 눈으로 확인할 수 있는 결과 하나에 스텝 하나. 레벨과 상관없이 같은 기준이다.

**시간**: 2시간 수업 기준으로 이야기·오늘 만들 것 10분, 개념 묶음 전체 75분 안팎, 완성 확인 10분, 확장 미션 15분, 제출 10분을 잡는다(Lv.3은 설계하기 10분을 더한다). 개념 묶음이 크게 넘치면 탐색과 꾸미기부터 줄인다.

**목차**: 개념 묶음 하나가 목차 하나다. 이야기(와 오늘 만들 것), 개념 묶음들, 마무리(완성 확인, 마무리 퀴즈), 더 해 보기(확장 미션, 심화 도전) 순서로 `unit.json`의 `chapters`에 적는다. 확인 퀴즈가 각 목차의 끝에 오게 한다. 학생 화면 위쪽에는 지금 목차 이름과 그 목차의 점만 보이고, "목차" 버튼으로 전체 목차를 펼쳐 통과한 스텝으로 돌아갈 수 있다.

**퀴즈 스텝의 동작**: 확인 퀴즈와 마무리 퀴즈는 보기 4개 중 하나를 고르는 문항을 2\~3개 둔다. 한 스텝의 문항을 모두 맞혀야 다음으로 넘어간다.

- 틀리면 어느 문항이 틀렸는지 빨간 표시나 개수로 알려 주지 않고, **틀린 문항 아래에 노란 칸으로 힌트**를 보여 준다. 힌트는 정답을 말하지 않고 다시 볼 곳을 짚어 준다(예: "`-5만큼 바꾸기`가 몇 번 있는지 세어 보세요").
- 통과하면 **모든 문항에 해설**을 보여 준다.
- 문항은 학생이 이야기나 자기 작품을 다시 보고 확인할 수 있는 것으로 낸다. 화면에 넣지 못한 문항은 강사용 안내서에 두고 수업 중에 말로 묻는다.

## 만들기 스텝의 틀

만들기 스텝은 칸 5개를 이 순서로 쓴다. 필수 칸은 모든 스텝에 있고, 선택 칸은 필요할 때만 넣되 순서는 바꾸지 않는다. 학생은 교안 패널(기본 폭 360px)에서 위에서 아래로 읽으므로, 순서가 곧 학생이 할 일의 순서다.

| 칸 | 이름 | 필수 | 블록 종류 | 쓰는 것 | 분량 |
| --- | --- | --- | --- | --- | --- |
| 0 | 스텝 제목 | 필수 | `title` | 이 스텝에서 할 일 | 15자 이내 |
| 1 | 목표 | 필수 | `text` | `**목표**` 다음 줄에 목록으로. 다 만들면 무엇이 보이는지. "확인"을 누르면 이것을 검사한다(통과 조건). "\~하면 \~가 \~해요" | 1\~3개 항목 |
| 2 | 미리보기 | Lv.1은 필수 | `image` (GIF) | 이 스텝을 끝낸 작품이 움직이는 모습 | 1개, 5초 안팎 반복 |
| 3 | 안내 | 필수 | `text` + `blocks` | 새 블록은 그림으로 보여 주고, 다시 쓰는 블록은 질문으로 묻는다 (레벨별 강도 참고) | 블록 그림 2개 이내 |
| 4 | 해 보기 | 필수 | `text` | `**확인**: …`(실행해서 무엇을 볼지), 필요하면 `**도전**: …`, `**해 보기**: …` | 1\~3문단 |

**칸별 규칙**

- **목표**: 눈으로 확인되는 결과로 쓴다. "반복을 배워요"(X) → "깃발을 누르면 고양이가 계속 걸어요"(O). 목표가 곧 통과 조건이다. 실패했을 때 무엇을 다시 볼지 알려 주는 칸이므로 해 보기에서 직접 볼 수 있는 것만 쓴다. 목표는 패널 맨 위에 둔다.
- **미리보기**: 완성작 전체가 아니라 이 스텝까지의 모습만. 다음 스텝의 답이 보이면 안 된다.
- **안내**: 블록이 어느 꾸러미에 있는지 → 어디에 붙이는지 → 왜 그런지(1문장) 순서로 쓴다. 개념 설명은 이 프로젝트에서 쓰는 만큼만.
- **해 보기**: `**확인**:`은 "깃발을 누르고 위쪽 화살표를 두 번 누르면 `각도`가 80인가요?"처럼 목표를 직접 확인하는 방법이다. `**도전**:`은 목표와 상관없는 탐색이다(예: "10을 30으로 바꾸면 어떻게 될까요?").

## 탐색 스텝

블록을 눌러 보거나 숫자를 바꿔 보며 결과를 관찰하는 스텝이다. 작품에 남는 것이 없고, 끝나면 꺼낸 블록을 지우거나 숫자를 되돌린다. 예상하고 → 해 보고 → 비교하는 것이 핵심이다.

- 칸 순서: 제목("탐색: …") → 안내(무엇을 어떻게 눌러 볼지) → 입력 표 → `**정리**:` 또는 `**되돌리기**:`(꺼낸 블록 지우기, 바꾼 숫자 되돌리기)
- **입력 표**(`record` 블록): 줄은 3개 안팎. 열은 "고정 칸(무엇을 해 볼지) → 내 예상 → 해 보니"다.
  - **내 예상**: 방향·위치처럼 고를 수 있는 것은 보기(`select`), 각도처럼 숫자로 답하는 것은 숫자(`number`)로 받는다. 자유롭게 쓰는 칸은 채점할 수 없으므로 쓰지 않는다.
  - **해 보니**: 예상을 적어야 열린다. 블록을 눌러 본 뒤 [맞았어요] / [달랐어요]를 누르고, 달랐을 때만 실제 값을 고른다. 같은 값을 두 번 적지 않게 하려는 것이다.
  - **채점**: 최종 값(맞았으면 예상, 달랐으면 실제 값)이 정답과 모두 같아야 통과한다. 예상이 틀린 것만으로는 실패하지 않는다. 스텝의 `checks`에 `{ "type": "record", "key": "record" }`를 둔다.
- 위쪽 그림에 답이 그려져 있는 값은 표에 넣지 않는다(예: 방향 그림에 있는 45, 90을 묻지 않음).
- 실험하며 작품을 바꾸는 탐색(반복 횟수 바꾸기 등)은 되돌렸는지 확인하는 동적 검사를 함께 둔다.
- 입력 표가 없는 탐색(손으로 눌러 보기만 하는 것)은 채점하지 않는다.

## 꾸미기 스텝

소리, 모양 바꾸기처럼 작품을 꾸미는 스텝이다. 다른 만들기처럼 채점하고, "선택", "건너뛰어도 돼요" 같은 말은 쓰지 않는다.

- 칸 순서: 제목("꾸미기: …") → 안내 + 블록 그림 → `**확인**:`
- 채점: 모양은 동작으로 확인한다(예: 쏜 뒤 원래 모양으로 돌아오는지). 소리처럼 동작으로 확인할 수 없는 것은 블록 검사로 확인한다.
- 꾸미기 때문에 이후 만들기 스텝의 검사가 실패하지 않게 쓴다(예: 깃발 스크립트에 원래 모양으로 바꾸기를 함께 넣게 한다).

## 다른 스텝 종류의 틀

| 스텝 종류 | 칸 순서 |
| --- | --- |
| 이야기 | 제목 → 이야기(인물이나 상황 → 궁금증 → 떠올린 생각 → 오늘 프로젝트와 연결) → 그림이나 사진 → `**어림해 보기**:`나 `**그림 보기**:` 질문(선택). 실제 사진은 스텝 끝에 출처를 한 줄로 적는다(예: `*사진: … © 저작자 (CC BY 3.0)*`). Lv.3은 그림 대신 `video`를 쓸 수 있다 |
| 오늘 만들 것 | `## 오늘 만들 게임` → 한 문장 소개 → 만드는 순서와 새로 배울 개념 → 완성작 미리보기 GIF |
| 완성 확인 | 제목 → 목표(필수 구현 전체) → 되돌리기 안내(꾸미기·실험에서 바꾼 것) → 기록표나 해 보기(처음부터 끝까지 실행) |
| 확장 미션 | 제목 → 안내 1문장("하나 이상 골라 해 보세요. 선생님께 보여 주세요") → 미션마다 `## ★ 미션 A. 이름` + 할 일 1\~2문장 + 필요하면 블록 그림 단서 |
| 심화 도전 | 제목 → 하는 일 → 블록 그림 → 생각해 볼 질문 → `**되돌리기**:`(원래 게임으로 돌아가는 법) |

**설계하기 스텝 (Lv.3)**

단순히 적어 두는 메모가 아니라, 프로젝트 완성까지 이끄는 질문들로 이루어진 스텝이다. 학생은 배움 노트처럼 문항마다 글로 답한다. 질문 1\~4가 입력 문항이고, 확인 질문은 답을 다 쓴 뒤 스스로 점검하는 데 쓴다. 모든 문항을 채워야 다음으로 넘어가고, 만드는 중에 다시 열어 고칠 수 있다. 큰 것에서 작은 것으로 차례대로 묻는다.

| 순서 | 정하는 것 | 이끄는 질문 |
| --- | --- | --- |
| 1 | 장면: 장면 목록, 장면마다 배경, 다음 장면으로 넘어가는 조건 | 화면이 크게 바뀌는 순간은 언제인가요? 시작할 때, 하는 중, 끝날 때 무엇이 보이나요? |
| 2 | 등장하는 것: 스프라이트, 나오는 장면, 하는 일, 모양 개수 | 그 장면에서 움직이거나 반응하는 것은 무엇인가요? 모습이 바뀌어야 하나요? |
| 3 | 기억할 것: 변수(값 하나), 리스트(값 여러 개) | 하는 동안 바뀌면서 기억해야 하는 숫자나 글자가 있나요? 여러 개를 차례로 꺼내 써야 하나요? |
| 4 | 만드는 순서: 기능 목록 ("\~하면 \~한다" 한 줄에 하나) | 무엇부터 만들면 바로 실행해 볼 수 있나요? |
| 확인 | 빠진 것 찾기 | "오늘 만들 것"의 필수 구현을 하나씩 보며: 이건 누가 하나요? |

- 칸 순서: 제목 → 안내 1문장 → 질문 1\~4 → 확인 질문 → 다른 프로젝트의 예시 (같은 프로젝트의 예시는 답이 되므로 쓰지 않는다)
- 장면이 하나뿐인 작품(그림판, 시뮬레이션 등)은 1번을 "장면 하나"로 두고 넘어간다.
- 질문은 모든 Lv.3 프로젝트에서 같다. 사이트에 고정되어 있어 교안에서는 `unit.json`에 `design` 스텝의 자리만 둔다(기획서 6장).

## 레벨별 안내 강도

틀(칸 순서)은 레벨과 상관없이 같고, 안내 칸에 얼마나 알려 주는지만 레벨마다 다르다. 처음 나오는 블록은 보여 주고, 다시 쓸 때는 질문하고, 레벨이 오를수록 질문을 늘린다.

| 상황 | Lv.1 | Lv.2 | Lv.3 |
| --- | --- | --- | --- |
| 새 블록 (처음 나옴) | 블록 그림 + 붙이는 위치 + 결과 | 블록 그림 + 결과. 위치는 질문 | 해당 없음 (새 블록 없음) |
| 다시 쓰는 블록 | 질문 + 꾸러미 이름 | 질문만 | 할 일만 ("\~가 \~하게 하세요") |
| 미리보기 GIF | 모든 만들기 스텝 + 오늘 만들 것(완성작) | 새 블록이 나오는 스텝 + 오늘 만들 것 | 오늘 만들 것에만 |
| 스텝 크기 | 결과 하나. 스크립트 전체를 보여 줘 내용은 많고, 3\~5분 | 결과 하나. 4\~5분 안팎 | 결과 하나 (후반은 둘까지). 내용은 적고 7\~10분 |

**같은 일을 레벨별로 쓴 예** (방향키로 움직이기)

- Lv.1: "**이벤트** 꾸러미의 `오른쪽 화살표 키를 눌렀을 때` 아래에 `x좌표를 10만큼 바꾸기`를 붙여요." + 블록 그림
- Lv.2: "방향키로 우주선이 움직이게 하세요. 왼쪽 키를 누르면 x는 어떻게 바뀌어야 할까요?"
- Lv.3: "방향키로 캐릭터가 움직이게 하세요."

## 콘텐츠 블록 규칙

교안 형식이 허용하는 블록은 `text`, `image`, `video`, `blocks`, `record` 다섯 가지다. 모든 글자는 `{ "ko", "en" }`으로 쓰고, 영어도 모든 문장을 채운다 (비어 있으면 한국어가 나오지만, 빠뜨린 것으로 본다).

| 블록 | 쓰는 곳 | 규칙 |
| --- | --- | --- |
| `text` | 목표, 안내, 해 보기, 이야기 | `text` 하나에 한 가지 일. 문장 수 제한은 두지 않되 한 문장에 행동 하나 |
| `image` | 미리보기, 이야기 그림·사진, 화면 위치 안내 | GIF는 5초 안팎 반복(완성작 GIF는 더 길어도 됨). 무대만 잘라 쓴다(메뉴·블록 영역 제외). `alt`는 "무엇이 어떻게 움직이는지" 1문장 |
| `video` | 이야기 스텝 (Lv.3) | 유튜브 링크, 3분 이내. 만들기 스텝에는 넣지 않는다 (GIF로 대신) |
| `blocks` | 안내, 확장 미션 단서, 퀴즈 | 그림 하나에 스크립트 하나. 블록 8개 이내, 그중 새 블록은 2개 이내. Lv.1에서 스크립트 전체를 보여 줄 때는 8개를 넘어도 된다. 언어마다 그 언어의 블록 이름으로 쓴다 |
| `record` | 탐색 스텝, 완성 확인의 기록표 | 학생이 직접 적는 표. 열마다 고정 글자 또는 입력 칸(`select`, `number`, `text`, `verify`). 정답(`answer`)이 있는 칸만 채점한다 (탐색 스텝 참고) |

**마크다운**: 굵게, 목록, 표, 코드 표기를 쓴다. `##` 제목은 이야기와 확장 미션에만 쓴다. 표는 안내표(과녁 자리처럼 읽기만 하는 표)에 쓰고, 학생이 적는 표는 `record`로 만든다.

**스크롤과 배치**: 스텝이 길어 스크롤하는 것은 괜찮다. 대신 목표는 패널 맨 위에 둔다. 스텝 길이를 숫자로 제한하지 않고, 너무 길다면 결과가 둘 이상 들어 있지 않은지 본다.

**파일 이름**: `media/s<스텝번호>-<내용>.gif` (예: `media/s03-preview.gif`, `media/s09-up.gif`)

## 소제목

문단 맨 앞에 굵은 소제목을 두면 학생 화면이 아이콘 칩과 색 상자로 그린다. 정해진 소제목만 쓰고, 형식을 지킨다.

| 소제목 | 쓰는 곳 | 형식 | 화면 |
| --- | --- | --- | --- |
| 목표 | 만들기, 완성 확인 맨 위 | `**목표**` 다음 줄에 `- 목록` | 파란 카드 (과녁 아이콘) |
| 확인 | 해 보기 칸, 꾸미기 | `**확인**: 문장` | 초록 상자 (체크 아이콘) |
| 도전 | 해 보기 칸 | `**도전**: 문장` | 주황 상자 (별 아이콘) |
| 해 보기 | 해 보기 칸 (실험해 볼 것) | `**해 보기**: 문장` | 보라 상자 (재생 아이콘) |
| 정리, 먼저 정리, 되돌리기 | 탐색 끝, 스텝 시작 전 정리, 심화 도전 끝 | `**정리**: 문장` | 회색 상자 (되돌리기 아이콘) |
| 어림해 보기, 그림 보기, 생각해 보기 | 이야기, 탐색 | `**어림해 보기**: 문장` | 하늘색 상자 (물음표 아이콘) |

영어는 같은 자리에 `**Goal**`, `**Check**:`, `**Challenge**:`, `**Try**:`, `**Clean up**:`, `**Undo**:`, `**Estimate**:`, `**Look**:`을 쓴다.

## 쓰기 규칙

| 항목 | 규칙 | 예 |
| --- | --- | --- |
| 문체 | 해요체. 학생에게 직접 말한다 | "붙여요", "눌러 보세요" |
| 문장 | 한 문장에 행동 하나. 25자 안팎 | "블록을 꺼내요. 깃발 블록 아래에 붙여요." |
| 블록 이름 | 코드 표기. 에디터에 보이는 이름, 입력 칸은 실제로 넣을 값으로 | `x좌표를 10만큼 바꾸기` |
| 변수 이름 | 코드 표기 | `각도`가 90이 돼요 |
| 꾸러미 이름 | 굵게. 처음 한 번은 색도 | **동작**(파란색) 꾸러미 |
| 화면 위치 | 학생 화면 기준 방향 + 이름 | "오른쪽 위 무대", "왼쪽 블록 꾸러미" |
| 스프라이트 | 시작 프로젝트의 이름 그대로, 굵게. 영어 글에는 뜻을 괄호로 | **대포**, **대포** (cannon) |
| 숫자 | 아라비아 숫자, 음수는 −가 아니라 키보드의 - | x: -120 |
| 낱말 | 처음 나오는 개념어는 굵게 + 한 줄 풀이. 그 뒤로는 같은 말만 쓴다 | **변수**: 값을 담아 두는 이름 붙은 상자 |
| 금지 | "쉽게", "간단히", "당연히" 같은 말 |  |

## 목표(통과 조건) 쓰는 법

목표 항목마다 `checks` 항목을 하나 이상 맞추고, 문장에 없는 것은 검사하지 않는다.

| 원칙 | 이유 |
| --- | --- |
| 결과를 검사한다 (동적 검사 우선) | 다른 블록으로 같은 결과를 낸 학생도 통과해야 한다 |
| 블록 검사(정적)는 새 블록이 나오는 스텝에만 | 새 블록을 처음 배우는 스텝에서는 그 블록을 써야 한다 |
| 동적 검사로 구분되지 않을 때만 예외로 정적 검사 | 시작 상태가 이미 목표와 같은 경우(예: 과녁이 처음부터 첫 자리에 있음), 소리처럼 동작으로 볼 수 없는 경우 |
| 느슨하게 쓴다 (위치는 ±5, 개수는 "이상") | 스텝 단위 예외가 없어 엄격하면 학생이 멈춘다 |
| 앞 스텝에서 통과한 것은 다시 검사하지 않는다 | 실패 원인이 지금 스텝에 있어야 학생이 고칠 곳을 안다 (완성 확인 스텝만 예외) |
| 시작 상태를 바꾼 뒤 검사한다 | 처음부터 목표 상태이면 아무것도 안 해도 통과한다 (예: 대포를 다른 쪽으로 돌린 뒤 깃발을 눌러 90인지 본다) |
| 스프라이트는 `@first`, `@any`. 여러 스프라이트를 구분해야 하면 이름 | 학생이 이름을 바꿔도 통과하게. 이름을 쓸 때는 시작 프로젝트의 이름 |
| 변수 이름과 말풍선 글자는 언어별 값 `{ "ko", "en" }` | 영어로 진행하는 학생도 교안대로 하면 통과해야 한다 |

| 목표 항목 (학생) | 채점 규칙 (`checks`) |
| --- | --- |
| 깃발을 누르면 탐험가가 가운데(0, 0)에 있어요 | 동적: `greenFlag` → `x eq 0`, `y eq 0` |
| 오른쪽 키를 누르면 오른쪽으로 움직여요 | 동적: `keyPress ArrowRight` → `x gt initial` |
| 과녁을 지날 때 "명중!"이라고 말해요 | 동적: 쏘기 → `sayText contains { "ko": "명중", "en": "Hit" }` |
| 탐색 표의 해 보니가 모두 맞아요 | 입력 표: `{ "type": "record", "key": "record" }` |

작성 순서: 정답 sb3를 먼저 만들고 → 목표 항목 → `checks` → 일부러 틀린 sb3 2\~3개로 실패하는지, 다른 풀이 1\~2개로 통과하는지 시험한다.

## 작성 체크리스트

교안 하나를 마칠 때마다 확인한다.

- [ ] 단원 흐름 순서대로 스텝이 놓였다 (이야기 → 오늘 만들 것 → 개념 묶음(탐색 → 만들기 → 꾸미기 → 확인 퀴즈) 되풀이 → 완성 확인 → 마무리 퀴즈 → 확장 미션 → 심화 도전 → 제출)
- [ ] `chapters`가 개념 묶음마다 하나이고, 확인 퀴즈가 목차의 끝에 온다
- [ ] 만들기 스텝이 결과 하나에 하나씩이고, 모두 필수 칸(제목, 목표, 안내, 해 보기)이 있다
- [ ] 퀴즈 스텝마다 2\~3문항이고, 문항마다 힌트(정답을 말하지 않음)와 해설이 있다
- [ ] 새 블록이 나오는 스텝마다 블록 그림이 있고, 한 스텝에 새 블록이 2개를 넘지 않는다
- [ ] 구성안의 "새로 만나는 개념"에 없는 개념을 쓰지 않았다 (쓴다면 구성안을 먼저 고친다)
- [ ] 다시 쓰는 블록은 레벨별 안내 강도에 맞게 질문으로 썼다
- [ ] 미리보기 GIF가 다음 스텝의 답을 보여 주지 않고, 오늘 만들 것에 완성작 GIF가 있다
- [ ] 목표가 맨 위에 있고, 소제목이 정해진 형식(`**확인**: …` 등)이다
- [ ] 목표 항목마다 `checks`가 있고, 문장에 없는 검사가 없다. 동적 검사로 구분되지 않는 곳만 정적 검사를 썼다
- [ ] 탐색 표는 예상 → 해 보니(맞았어요/달랐어요) 형식이고, 위쪽 그림에 답이 있는 값을 묻지 않는다
