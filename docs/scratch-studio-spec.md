# 스크래치 스튜디오 기획서

작성일: 2026-10-04
최종 수정: 2026-10-15 — 「스크래치 학생용 교안 틀」(`scratch-lesson-template.md`)에 맞춰 과목명, 미니퀴즈 동작과 작성 방식, Lv.3 설계하기 스텝, 교안 폴더와 예시를 반영

## 1. 개요

스크래치 스튜디오는 `dlab-coding-track`의 스크래치 과목에서, 스텝 교안과 스크래치 에디터를 한 화면에 보여주고 스텝마다 학생 작품을 자동 채점하는 모듈이다. 학습 화면은 기존 튜토리얼 진행 화면을 쓰지 않고 본 사이트에 스크래치 전용으로 따로 만든다. 학생은 스텝마다 "확인"을 눌러 통과해야 다음 스텝으로 넘어간다.

이 문서는 에디터 저장소(`scratch-studio`) 전체와, 본 사이트에서 스크래치 과목일 때만 해당하는 동작을 정의한다. 같은 내용을 두 문서에 적지 않으며, 주제마다 한 문서가 기준이다.

- **교안 틀(`scratch-lesson-template.md`)이 기준**: 단원의 스텝 종류와 순서, 스텝 안의 칸 구성, 교안 문장과 채점 규칙을 쓰는 법
- **이 문서가 기준**: 스크래치 학습 화면, 채점, 작품 저장과 제출 버전, 작품 페이지에서 에디터를 쓰는 방법, 교안 형식과 가져오기, 메시지 규약, 다국어, 구현 단계
- **본 사이트의 `spec.md`(`docs/spec.md`)가 기준**: 계정·반·권한(§4), 데이터 모델(§5), 포트폴리오와 리포트(§3.5, §3.6), 작품 공유와 커뮤니티(§3.7)

`spec.md`가 기준인 내용은 여기에 다시 적지 않고 절 번호로 가리킨다. 이 문서의 원본은 비공개인 본 사이트 저장소의 `docs/scratch-studio/`에 두며, 공개 저장소인 `scratch-studio`에는 넣지 않는다.

- **대상 과목**: `SUBJECT.editor_type = scratch`인 과목(스크래치 Lv.1, Lv.2, Lv.3). 엔트리, 레고코딩 등 다른 튜토리얼형 과목은 기존 링크 제출 방식을 유지한다.
- **기기**: PC와 크롬북. 태블릿은 지원하지 않는다.
- **언어**: 스크래치 교안과 에디터는 한국어와 영어. 학습 화면의 버튼과 안내 문구를 포함해 사이트의 나머지 화면은 한국어만.

범위는 다음과 같다.

- `scratch-studio` 저장소: 에디터 빌드(편집, 실행 전용, 블록 보기 모드), 본 사이트와 통신하는 브리지, 채점 엔진
- 본 사이트: 스크래치 전용 학습 화면(교안 패널 + 에디터 연결), 채점 요청과 결과 기록, 작품 자동 저장, 교안 가져오기 스크립트, 프로젝트 제출과 버전 이력, Lv.3 설계하기 입력 폼
- 본 사이트: 공유 신청과 교사 승인, 커뮤니티 페이지, 작품 페이지, 좋아요와 댓글, 교사의 작품 열람 (공유와 커뮤니티의 동작은 `spec.md` §3.7이 기준이고, 이 문서는 구현 순서만 다룬다)
- 구조 검증용 샘플 단원 1개 (실제 수업의 첫 단원)

만들지 않는 것은 다음과 같다.

- 교사의 실시간 관찰과 제어권 교환
- 교사가 화면에서 채점 규칙을 만드는 편집기
- 리믹스, 팔로우, 신고, 댓글의 답글, 검색엔진 노출
- 스크래치 외 과목의 커뮤니티 공유 (추후 확장)
- 점수, 부분 점수, 힌트, 스텝 단위 수동 통과
- 스크래치 스텝의 개념 태그와 잘한 점/보완할 점 분석
- 태블릿 지원과 좁은 화면용 배치
- 학습 화면의 버튼과 안내 문구의 영어 번역 (첫 버전은 한국어만)

## 2. 확정된 결정 사항

아래 항목은 확정했으므로 구현 중에 임의로 바꾸지 않는다.

| 항목 | 결정 |
| --- | --- |
| 서비스 이름 | 스크래치 스튜디오. 코드에서는 `scratch-studio`, `ScratchStudio` |
| 구조 | 에디터는 별도 공개 저장소와 서브도메인으로 분리, 본 사이트는 비공개 |
| 공개 범위 | 에디터 저장소만 GPLv3로 공개. 교안과 채점 규칙은 비공개 |
| 대상 과목 | 스크래치 Lv.1, Lv.2, Lv.3 (모두 일반 스크래치 사용) |
| 교안과 채점 규칙 작성 | 개발자가 JSON으로 작성해 가져오기 스크립트로 반영. 미니퀴즈 문항도 같은 JSON에 작성 |
| 교안 콘텐츠 | 텍스트, 이미지/GIF, 영상(유튜브 링크), 스크래치 블록 그림 |
| 시작 프로젝트 | 단원마다 제공 여부를 선택 |
| 학습 화면 | 본 사이트에 스크래치 전용 화면을 따로 만듦. 기존 튜토리얼 진행 화면은 쓰지 않고 고치지도 않음 |
| 채점 시점 | "확인" 버튼을 눌렀을 때만 |
| 채점 결과 표시 | 통과/실패만 |
| 스텝 잠금 | 통과해야 다음 스텝. 스텝 단위 예외 없음 |
| 채점 방식 | 규칙 기반(정적 + 동적). LLM은 사용하지 않음 |
| 교사 개입 | 실시간 개입 없음. 제출한 버전과 작업 중인 저장본은 열어볼 수 있음 |
| 작품 보관 | 학생 × 단원마다 작업 중인 최신 저장본 1개(`SCRATCH_PROJECT`) + 제출할 때마다 쌓이는 버전 이력(`PROJECT_VERSION`, 작품당 최근 10개) |
| 영상 | 파일로 보관하지 않고 유튜브 링크만 사용 (작품 영상, 교안 영상 모두) |
| 라이선스 해석 | 에디터와 본 사이트를 분리해 메시지로만 통신하면 별개의 프로그램이라는 일반적인 해석을 따름. 별도의 법률 확인은 하지 않음 |

작품 공유, 커뮤니티 페이지, 닉네임, 좋아요와 댓글, 리포트에 관한 결정은 `spec.md` §3.6과 §3.7에 있다.

## 3. 구조와 라이선스

모듈은 두 부분으로 나뉜다. 에디터는 상태가 없는 정적 앱이고, 데이터와 권한은 전부 본 사이트가 갖는다.

|  | 에디터 (`scratch-studio`) | 본 사이트 (`dlab-coding-track`) |
| --- | --- | --- |
| 저장소 | 공개, GPLv3 | 비공개 |
| 주소 | 별도 서브도메인 (예: `studio.<도메인>`) | 기존 주소 |
| 내용 | TurboWarp scratch-gui 포크 빌드, 브리지, 채점 엔진 | 스크래치 전용 학습 화면, API, DB, 파일 저장 |
| 로그인, DB, 서버 통신 | 없음 | 기존 체계 그대로 |
| 아는 것 | 지금 열린 작품과 받은 채점 규칙 | 학생, 교안, 채점 규칙, 진도, 작품 파일 |

**동작 원칙**

- 본 사이트의 학습 화면이 에디터를 iframe으로 띄우고, 둘은 `postMessage`로만 통신한다(4장).
- 에디터는 본 사이트의 API를 직접 호출하지 않는다. 작품을 불러오고 저장하는 것, 진도를 기록하는 것은 모두 본 사이트 코드가 한다.
- 본 사이트에는 에디터와 통신하는 얇은 클라이언트(`ScratchStudioFrame` 컴포넌트)만 둔다. 에디터나 채점 엔진의 코드를 본 사이트 저장소로 복사하지 않는다.
- 동적 채점용 두 번째 실행 환경은 에디터가 자기 안에서 필요할 때 만들고 채점이 끝나면 없앤다. 본 사이트는 그 존재를 몰라도 된다.

**보안**

- 에디터는 본 사이트와 다른 서브도메인에서 제공하고, 본 사이트의 세션 쿠키에는 도메인(`Domain` 속성)을 지정하지 않는다. 쿠키는 도메인 기준으로 전달되므로, 이 조건을 지켜야 에디터 쪽에서 세션 쿠키가 보이지 않는다.
- 양쪽 모두 `postMessage`의 상대 출처를 허용 목록으로 검증한다. 허용 출처는 에디터의 빌드 설정과 본 사이트의 환경 변수로 지정한다.
- 에디터는 `frame-ancestors`로 본 사이트에서만 임베드되게 한다. 이 설정은 HTTP 응답 헤더로만 동작한다.
- TurboWarp의 사용자 확장 기능 불러오기는 끈다. 임의의 자바스크립트를 실행할 수 있기 때문이다.

**라이선스**

에디터 저장소는 GPLv3로 공개한다. TurboWarp의 수정분은 GPLv3이고, 그 안에 포함된 스크래치 원본 코드는 BSD 3-Clause다([TurboWarp/scratch-gui 저장소](https://github.com/TurboWarp/scratch-gui)). 학원의 유료 수업에 써도 조건은 같다.

본 사이트는 에디터 코드를 포함하지 않고 메시지로만 통신하므로 비공개로 둔다. 이렇게 분리하면 별개의 프로그램으로 본다는 일반적인 해석을 따르기로 했고, 별도의 법률 확인은 하지 않는다. 법적 보증은 아니므로 분리 원칙(코드 복사 금지, 메시지로만 통신)을 지킨다.

Scratch 로고와 고양이 캐릭터를 학원 서비스의 로고나 마스코트로 쓰지 않고, Scratch 공식 서비스나 제휴처럼 보이게 표현하지 않는다. 과목명과 화면 문구에서 스크래치를 가리키는 것은 괜찮다.

**참고할 기존 프로젝트**

[Blockflow](https://github.com/openpatch/blockflow)는 스크래치 에디터에 단계별 튜토리얼을 넣은 AGPL 포크다. 채점 기능은 없지만 에디터 설정 방식을 참고할 수 있다.

## 4. 메시지 규약

본 사이트와 에디터는 아래 12가지 메시지만 주고받는다. 이 규약이 두 저장소 사이의 유일한 계약이므로, 타입 정의를 `scratch-studio` 저장소의 `protocol.ts`에 두고 본 사이트는 같은 정의를 그대로 따른다.

모든 메시지는 `{ source: "scratch-studio", version: 1, type, requestId, payload }` 형태다. 요청에 대한 응답은 같은 `requestId`를 쓴다.

| 방향 | `type` | `payload` | 설명 |
| --- | --- | --- | --- |
| 에디터 → 사이트 | `ready` | 없음 | 에디터 로딩 완료. 사이트는 이 메시지를 받은 뒤에 요청을 보낸다 |
| 사이트 → 에디터 | `init` | `locale`, `mode` | 언어와 모드 설정. 모드는 `edit`(편집), `player`(실행 전용), `view`(블록 보기) |
| 사이트 → 에디터 | `loadProject` | `sb3`(ArrayBuffer 또는 null) | 작품 열기. null이면 빈 프로젝트 |
| 에디터 → 사이트 | `projectChanged` | 없음 | 작품이 바뀜. `edit` 모드에서만 보낸다 |
| 사이트 → 에디터 | `exportProject` | 없음 | 현재 작품 요청. 응답 `payload`는 `sb3`(ArrayBuffer) |
| 사이트 → 에디터 | `captureStage` | 없음 | 무대 화면 캡처 요청. 응답 `payload`는 `png`(ArrayBuffer). 썸네일용 |
| 사이트 → 에디터 | `grade` | `checks` | 채점 요청. 응답 `payload`는 `result`(`pass`, `fail`, `error`), `checkResults`, `sb3` |
| 사이트 → 에디터 | `setMode` | `mode` | 모드 전환. 작품 페이지의 "블록 보기"에 쓴다 |
| 에디터 → 사이트 | `localeChanged` | `locale` | 학생이 에디터의 언어 메뉴에서 언어를 바꿈. 사이트는 교안을 같은 언어로 바꾸고 선택을 저장한다 |
| 에디터 → 사이트 | `saveRequested` | 없음 | 학생이 에디터 메뉴 바의 "저장하기" 또는 "다시 시도"를 누름. 사이트는 `exportProject`로 작품을 받아 저장한다 |
| 사이트 → 에디터 | `setSaveStatus` | `status`(`saved`, `saving`, `failed`) | 에디터 메뉴 바의 저장 상태 표시를 바꾼다. `saving`이면 "저장하기"를 비활성화하고, `failed`이면 "다시 시도"를 보여준다 |
| 에디터 → 사이트 | `error` | `code`, `message` | 처리 실패. 요청에 대한 것이면 같은 `requestId` |

- sb3는 ArrayBuffer를 transferable로 넘겨 복사 비용을 없앤다.
- 사이트는 요청마다 제한 시간을 둔다. `loadProject`와 `exportProject`는 15초, `grade`는 동적 검사마다 제한 시간에 반복 횟수(`runs`)를 곱한 값을 모두 더하고 5초를 더한 값이다. 넘으면 학생에게 다시 시도하라고 안내한다.
- `saveRequested`와 `setSaveStatus`는 `edit` 모드에서만 쓴다. `player`와 `view` 모드에서는 저장 상태와 "저장하기"를 보여주지 않는다.
- 위 두 메시지는 0단계 검증 결과에 따라 바뀔 수 있다. 저장 버튼과 저장 상태 표시는 에디터에 이미 있는 것(scratch-gui의 저장 가능 설정)을 켜서 쓰는 것을 먼저 시도한다.
- 규약을 바꿀 때는 `version`을 올리고, 에디터는 모르는 `version`의 메시지에 `error`로 답한다.

## 5. 학습 화면과 작품 페이지

학습 화면은 기존 튜토리얼 진행 화면을 확장하지 않고, 본 사이트에 **스크래치 전용 학습 화면**으로 새로 만든다. 교안 패널, 버튼, 배치를 에디터에 맞춰 따로 디자인한다.

- 단원 목록에서 과목의 `editor_type`이 `scratch`인 단원을 열면 전용 화면으로 들어간다. 그 외 과목은 기존 튜토리얼 진행 화면으로 들어가며, 기존 화면의 코드와 동작은 바꾸지 않는다.
- 화면만 따로이고 데이터는 같다. 진도(`STEP_PROGRESS`, `UNIT_PROGRESS`), 미니퀴즈(`QUIZ`), 프로젝트 제출(`PROJECT`)은 기존 테이블과 API를 쓴다.
- 전용 화면은 에디터 저장소가 아니라 본 사이트 저장소에 둔다. 교안 내용이 에디터로 넘어가지 않으므로 메시지 규약(4장)은 그대로다.

**배치**

- 왼쪽은 전용 화면의 스텝 교안 패널, 오른쪽은 에디터 iframe이다. 패널 너비는 기본 360px이고 경계선을 끌어 300~560px 사이에서 조절하며, 접으면 에디터가 전체 너비를 쓴다. 접은 동안에는 그 자리에 너비 56px의 띠를 남기고, 위에서부터 "종료" 버튼, "교안 열기" 버튼, 스텝 점(세로), 현재 스텝 표시(예: "2/6")를 둔다. 띠는 본 사이트가 그린다.
- 스텝 교안은 `LESSON_STEP.content`의 블록(텍스트, 이미지/GIF, 영상, 블록 그림)을 순서대로 그린다. 블록 그림은 scratchblocks 라이브러리로 렌더링한다. 영상은 유튜브 플레이어를 끼워 넣어 보여준다.
- 스텝 중간 미니퀴즈는 교안 패널 안에서 푼다. 화면 동작은 채점 스텝과 같다. 한 퀴즈 스텝의 문항(보기 4개 중 하나)을 모두 고르고 "확인"을 누르면 결과 띠로 통과 또는 실패를 보여주고, 통과해야 "다음"이 활성화된다. 모든 문항을 맞혀야 통과다. 실패해도 해설이나 어느 문항이 틀렸는지는 보여주지 않는다(교안 틀의 "퀴즈 스텝의 동작"). 기록 규칙은 기존 튜토리얼과 같다.
- 언어 전환 버튼은 따로 두지 않는다. 학생이 에디터의 언어 메뉴에서 한국어나 영어를 고르면 교안도 같은 언어로 바뀐다(9장).
- 사이드바와 상단 바가 없는 전체 화면이다. 교안 패널 맨 위 줄에 "종료"(단원 목록으로), 단원 제목, 패널 접기 버튼을 둔다. 패널을 접어도 "종료"는 접힌 띠에 남는다.
- 저장 상태(저장됨, 저장 중, 저장 실패)와 "저장하기" 버튼은 에디터 메뉴 바의 오른쪽에 둔다. 저장 실패일 때는 그 옆에 "다시 시도"를 보여준다. 이 셋은 에디터가 그리고(나머지 버튼은 모두 본 사이트가 그린다), 본 사이트와는 메시지로 주고받는다(4장).
- 교안 패널 위쪽에 스텝마다 점을 하나씩 두어 진행을 보여준다(통과, 현재, 잠김). 미니퀴즈, 설계하기, 프로젝트 제출도 각각 한 스텝으로 센다. 패널 아래쪽에 "이전", "확인" 또는 "다음" 버튼을 둔다.
- 교안 패널은 단순하게 하고, 화면의 중심은 에디터에 둔다.
- 태블릿과 좁은 화면용 배치는 만들지 않는다. 화면이 좁으면 패널을 접어 쓴다.

**들어올 때**

1. 학생의 저장본(`SCRATCH_PROJECT`)이 있으면 그것을, 없으면 단원의 시작 프로젝트를, 그것도 없으면 빈 프로젝트를 연다.
2. 완료되지 않은 첫 스텝을 보여준다(기존 이어서 하기와 같다).

**확인 버튼**

1. 채점 규칙이 있는 스텝에서는 "확인" 버튼을 보여준다. 채점 규칙이 없는 스텝(이야기, 오늘 만들 것, 확장 미션 등)은 읽고 "다음"으로 넘어가며, "다음"을 누를 때 그 스텝을 완료로 기록한다.
2. 누르면 서버에서 그 스텝의 채점 규칙을 받아 에디터에 `grade`를 보낸다. 채점 중에는 버튼을 비활성화하고 진행 표시를 보여준다.
3. 결과와 함께 받은 작품을 서버에 보낸다. 서버는 시도 횟수를 올리고, 통과면 스텝을 완료 처리하고, 작품을 최신 저장본으로 저장한다.
4. 학생에게는 통과 또는 실패만 보여준다. 결과는 팝업이 아니라 교안 패널 아래쪽, 버튼 위의 결과 띠로 보여준다. 문구는 통과 "통과했어요", 실패 "아직이에요. 다시 해 보세요", 오류 "확인하지 못했어요. 다시 눌러 주세요"다. `error`는 시도 횟수에 넣지 않는다.
5. 통과해야 "다음"이 활성화된다. 이미 통과한 스텝으로는 자유롭게 돌아갈 수 있다.

**설계하기 (Lv.3)**

- `kind`가 `design`인 스텝이다. 교안 틀의 "설계하기 스텝" 문항(장면, 등장하는 것, 기억할 것, 만드는 순서)을 입력 칸으로, 확인 질문을 입력 칸 아래 안내로 보여준다. 문항은 모든 프로젝트에 같으므로 본 사이트 코드에 ko/en으로 고정해 두고 교안 JSON에는 넣지 않는다.
- 입력 칸을 모두 채우고 "다음"을 누르면 답을 저장하고 스텝을 완료로 기록한다. 하나라도 비어 있으면 "다음"이 비활성화된다.
- 완료한 뒤에도 "이전"이나 스텝 점으로 돌아와 고칠 수 있다. 고친 답은 "다음"을 누르거나 입력을 멈춘 뒤 자동으로 저장한다.
- 답은 학생 × 스텝마다 하나(`DESIGN_NOTE`, `spec.md` §5)이고 채점하지 않는다. 교사와 관리자는 학생 상세 화면에서 읽을 수 있다.

**저장**

- `projectChanged`를 받은 뒤 30초마다 `exportProject`로 작품을 받아 서버에 저장한다. 변경이 없으면 저장하지 않는다.
- 화면을 떠날 때 따로 저장하지 않는다. 저장되지 않은 변경이 남아 있으면 브라우저의 기본 경고 창을 띄운다.
- 학생이 "저장하기"를 누르면(`saveRequested`) 주기를 기다리지 않고 바로 저장한다. 변경이 없어도 저장한다.
- 저장을 시작하고 끝낼 때마다 `setSaveStatus`로 에디터에 상태를 알린다.
- 저장 실패는 화면에 표시하고 다음 주기에 다시 시도한다. 학생이 "다시 시도"를 누르면 바로 다시 저장한다.

**프로젝트 제출**

- 프로젝트 제출 스텝에서는 공유 링크 입력 대신 작품 제목, 배움 노트 2문항("오늘 배운 내용과 재밌었던 점", "무엇이 어려웠고 어떻게 해결했나요"), 영상 링크를 받는다. 제목과 배움 노트 2문항은 필수이고 영상 링크는 선택이다. 배움 노트는 기존 튜토리얼 제출 폼과 같은 방식으로 `PROJECT.student_note`에 저장한다.
- 제출을 마치면 패널에 무대 화면 썸네일, 제목, "제출했어요", 제출 횟수와 마지막 제출 시각(예: "3번째 제출 · 10월 3일 오후 4:12")을 보여준다. 하단의 주 버튼은 "단원 목록으로"이고 "이전"으로 앞 스텝에 돌아갈 수 있다. 다시 들어와 제출 스텝을 열어도 이 상태를 보여준다.
- 다시 제출하려면 제출 완료 상태의 "다시 제출하기" 버튼을 누른다. 이전에 쓴 제목, 배움 노트, 영상 링크가 채워진 폼이 열리고, 하단 버튼은 "취소"와 "다시 제출"로 바뀐다. 취소하면 고친 내용을 버리고 제출 완료 상태로 돌아간다. 다시 제출을 마치면 결과 띠로 "다시 제출했어요."를 보여준다.
- 제출하면 본 사이트가 `exportProject`로 받은 작품을 새 **버전**(`PROJECT_VERSION`)으로 저장하고, `captureStage`로 받은 무대 화면을 그 버전의 썸네일로 저장한다.
- 제출할 때마다 버전이 하나씩 쌓인다. 작업 중인 저장본이 이후에 바뀌어도 제출한 버전들은 그대로다.
- 한 작품당 최근 10개 버전만 보관하고 더 오래된 버전부터 지운다. 공개 중인 버전, 공유 신청 중인 버전, 학부모 리포트에 실린 버전은 지우지 않는다.
- 영상은 선택 사항이고 파일이 아니라 유튜브 링크로 받는다. 학생이 제출 화면에서, 교사가 학생 상세 화면에서 입력하거나 교체할 수 있다.
- 학습 시간은 기존 튜토리얼과 같은 방식으로 `UNIT_PROGRESS.time_spent`에 누적한다.

**작품 공유와 커뮤니티**

보호자 동의, 공유 신청과 교사 승인, 커뮤니티 페이지, 닉네임, 좋아요와 댓글, 요청에 의한 삭제, 누가 무엇을 볼 수 있는지는 `spec.md` §3.7을 따른다. 이 문서에는 에디터를 쓰는 방법만 적는다.

**작품 페이지**

- 에디터를 `player` 모드로 띄워 무대, 초록 깃발, 멈춤 버튼만 보여준다. 아래에 제목, 닉네임, 배움 노트를 둔다.
- "블록 보기"는 로그인한 학원 구성원에게만 보여준다. 누르면 `setMode`로 `view` 모드로 바꾸고, 여기서 고친 내용은 저장되지 않는다.
- 본인, 교사, 관리자에게는 버전 목록을 보여주고, 버전을 고르면 그 버전의 파일을 `loadProject`로 연다.
- 포트폴리오와 학부모 리포트는 스크래치 결과물을 썸네일로 보여주고, 누르면 이 작품 페이지를 연다. 포트폴리오는 최신 제출 버전을, 학부모 리포트는 그 리포트가 생성된 시점의 버전을 연다.

**교사의 작품 열람**

- 교사와 관리자는 학생 상세 화면에서 그 학생의 제출 버전 목록과 작업 중인 최신 저장본을 열 수 있다.
- 교사용 에디터는 따로 없다. 같은 에디터를 `view` 모드로 열고, 교사가 고친 내용은 저장되지 않는다.
- 작업 중인 저장본은 마지막 자동 저장 시점의 것이라, 학생 화면과 최대 30초 차이가 날 수 있다.

## 6. 교안 형식과 가져오기

개발자가 단원 하나를 폴더 하나로 작성하고, 가져오기 스크립트가 이를 본 사이트 DB의 `UNIT`, `LESSON_STEP`, `QUIZ_QUESTION`에 반영한다. 교안 폴더는 비공개로 관리하며 공개 저장소에 넣지 않는다. 스텝의 종류와 순서, 칸 구성, 문장 쓰는 법은 「스크래치 학생용 교안 틀」([scratch-lesson-template.md](scratch-lesson-template.md))을 따른다.

```
scratch-content/
  scratch-lv1/                (과목)
    01-treasure-map/          (단원)
      unit.json
      starter.sb3             (선택)
      media/
        s3-arrow-move.gif
      tests/                  (가져오지 않음. 채점 규칙 시험용)
        solution.sb3
        wrong-*.sb3
        alt-*.sb3
```

`tests/`에는 정답 작품, 일부러 틀린 작품, 다른 풀이를 둔다. 정답과 다른 풀이는 모든 스텝을 통과하고, 틀린 작품은 해당 스텝에서 실패해야 한다(교안 틀의 "작성 순서", 7장 "테스트").

**단원 JSON 예시**

교안 틀의 단원 흐름 중 앞부분만 줄여 보인 것이다. 만들기 스텝의 전체 예시는 교안 틀의 "예시: 보물 지도 탐험 스텝 3"에 있다.

```json
{
  "subject": "scratch-lv1",
  "unitKey": "01-treasure-map",
  "order": 1,
  "title": { "ko": "보물 지도 탐험", "en": "Treasure Map Quest" },
  "starterProject": "starter.sb3",
  "steps": [
    {
      "key": "s1",
      "title": { "ko": "천장의 파리", "en": "The Fly on the Ceiling" },
      "content": [
        { "type": "text", "value": { "ko": "…", "en": "…" } },
        { "type": "image", "src": "media/s1-story.png", "alt": { "ko": "…", "en": "…" } }
      ]
    },
    {
      "key": "q1",
      "kind": "quiz",
      "questions": [
        {
          "key": "q1-1",
          "question": { "ko": "…", "en": "…" },
          "options": [{ "ko": "…", "en": "…" }, { "ko": "…", "en": "…" }, { "ko": "…", "en": "…" }, { "ko": "…", "en": "…" }],
          "answer": 2
        }
      ]
    },
    {
      "key": "s3",
      "title": { "ko": "방향키로 움직이기", "en": "Move with arrow keys" },
      "content": [
        { "type": "text", "value": { "ko": "**목표**\n- 방향키 네 개를 누르면 탐험가가 각각 그쪽으로 움직여요.", "en": "**Goal**\n- Each of the four arrow keys moves the explorer in its direction." } },
        { "type": "blocks", "value": { "ko": "[오른쪽 화살표 v] 키를 눌렀을 때\nx 좌표를 (10) 만큼 바꾸기", "en": "when [right arrow v] key pressed\nchange x by (10)" } }
      ],
      "checks": [
        {
          "type": "dynamic",
          "actions": [
            { "do": "greenFlag" },
            { "do": "keyPress", "key": "ArrowRight", "durationMs": 100 },
            { "do": "wait", "ms": 300 }
          ],
          "expect": [
            { "target": "sprite", "sprite": "@first", "property": "x", "op": "gt", "value": { "ref": "initial" } }
          ],
          "timeoutMs": 3000
        }
      ]
    }
  ]
}
```

Lv.3 단원은 "오늘 만들 것" 스텝 뒤에 `{ "key": "d1", "kind": "design" }`을 둔다. 문항은 본 사이트에 고정되어 있으므로 다른 필드는 없다(5장 "설계하기").

**필드 규칙**

- 화면에 보이는 글자는 모두 `{ "ko": ..., "en": ... }` 형태다. `text`는 마크다운을 지원하되, 교안에서는 굵게와 목록만 쓴다.
- 스텝의 `kind`는 `lesson`(기본, 생략 가능), `quiz`, `design` 세 가지다.
- `lesson` 스텝의 `content`의 `type`은 `text`, `image`, `video`, `blocks` 네 가지다. `video`는 파일이 아니라 유튜브 주소(`youtube`)로 적는다. `blocks`는 scratchblocks 문법으로 쓰고, 언어마다 그 언어의 블록 이름으로 적는다.
- `quiz` 스텝은 `questions`만 갖는다. 문항마다 `key`, `question`, 보기 4개(`options`), 정답 보기의 번호(`answer`, 0부터)를 쓴다. 가져오면 바로 앞 `lesson` 스텝에 붙는 미니퀴즈 문항(`QUIZ_QUESTION.step_id`)이 된다. 그래서 `quiz` 스텝은 단원의 첫 스텝이 될 수 없다.
- `design` 스텝은 `key`와 `kind`만 갖고, `LESSON_STEP.kind = design`인 행이 된다.
- `starterProject`는 선택이다. 없으면 빈 프로젝트로 시작한다.
- `checks`는 모두 통과해야 스텝 통과다. 여러 풀이를 허용하려면 `{ "type": "anyOf", "checks": [...] }`로 묶는다. `checks`가 없으면 읽고 넘어가는 스텝이다.
- 스프라이트는 이름 대신 `@first`, `@stage`, `@any`로 가리킬 수 있다.
- 프로젝트 제출은 이 JSON에 넣지 않고 본 사이트의 기존 기능으로 단원 끝에 배치한다.

**가져오기 스크립트**

- 본 사이트 저장소에 `npm run import:scratch -- <폴더>`를 둔다. 스키마(zod) 검증에 실패하면 파일과 위치를 알리고 아무것도 바꾸지 않는다.
- `subject`로 과목을, `unitKey`와 스텝의 `key`, 퀴즈 문항의 `key`로 기존 행을 찾아 갱신한다(없으면 생성). 그래서 교안을 고쳐 다시 가져와도 학생의 `STEP_PROGRESS`가 유지된다. 이를 위해 `UNIT`, `LESSON_STEP`, `QUIZ_QUESTION`에 가져오기용 키 컬럼을 둔다(`spec.md` §5).
- 영어 값이 비어 있는 글자가 있으면 가져오기는 하되 파일과 위치를 경고로 알린다. 화면에서는 한국어로 대체되지만, 교안 틀은 이를 빠뜨린 것으로 본다.
- JSON에서 사라진 스텝과 퀴즈 문항은 지우지 않고 목록으로 알려, 개발자가 확인한 뒤 따로 지운다.
- 이미지와 시작 프로젝트는 본 사이트의 파일 저장소에 올리고 경로를 기록한다. 본 사이트에는 아직 파일 저장 기능이 없으므로 새로 정해야 한다(11장).
- 교안 관리 화면에서 스크래치 과목의 스텝과 미니퀴즈는 읽기 전용으로 보여준다. 화면에서 고치면 다음 가져오기 때 덮어써지기 때문이다.

## 7. 채점 엔진

채점 엔진은 프로젝트 JSON을 읽는 정적 검사와 프로젝트를 실제로 실행하는 동적 검사로 이루어지고, 결과는 통과 또는 실패 하나로 합쳐진다. 엔진은 UI와 분리된 순수 TypeScript 모듈(`grader/`)로 만들어 단위 테스트가 가능해야 한다.

채점 엔진은 `scratch-studio` 저장소에 있고 에디터 안에서 실행된다. 본 사이트는 4장의 `grade` 메시지로만 채점을 요청하며, 채점 규칙의 형식은 6장의 `checks`다.

**정적 검사 규칙**

입력은 `vm.toJSON()`으로 얻은 프로젝트 JSON이다. 블록 판별은 opcode로 하므로 에디터 언어와 무관하다.

| 규칙 | 의미 | 주요 옵션 |
| --- | --- | --- |
| `hasBlock` | 특정 블록이 있다 | `opcode`, `sprite`, `minCount`, `fields`, `inputs` |
| `notHasBlock` | 특정 블록이 없다 | `opcode`, `sprite` |
| `blockCount` | 블록 개수가 범위 안이다 | `opcode`, `min`, `max` |
| `sequence` | 한 스크립트 안에 블록들이 주어진 순서로 있다 | `opcodes`, `strict`(사이에 다른 블록 허용 여부) |
| `inside` | 감싸는 블록 안에 특정 블록이 있다 | `parent`, `child` |
| `underHat` | 특정 모자 블록 아래 스크립트에 블록이 있다 | `hat`, `opcode` |
| `variableExists` | 변수나 리스트가 있다 | `kind`, `name`(선택) |
| `spriteCount` | 스프라이트 수가 범위 안이다 | `min`, `max` |

공통 사항은 다음과 같다.

- 기본적으로 모자 블록에 연결된 스크립트만 센다. 작업 공간에 떨어져 있는 블록은 `includeDetached: true`일 때만 포함한다.
- `fields`는 드롭다운 값(예: 키 종류), `inputs`는 숫자·문자 입력값을 비교한다. 입력값은 `eq`, `gt`, `lt`, `between` 비교를 지원한다.
- `sprite`를 생략하면 `@any`로 본다.

**동적 검사**

동적 검사는 `actions`를 순서대로 실행한 뒤 `expect`의 조건을 모두 확인한다.

| 액션 | 의미 |
| --- | --- |
| `greenFlag` | 초록 깃발 클릭 |
| `keyPress` | 키를 `durationMs` 동안 누름 |
| `clickSprite` | 스프라이트 클릭 |
| `mouseMove` | 무대 좌표로 마우스 이동 |
| `answer` | 묻고 기다리기 블록에 답 입력 |
| `broadcast` | 메시지 방송 |
| `wait` | `ms`만큼 대기 |
| `stop` | 모두 멈추기 |

| 확인 대상 | 속성 |
| --- | --- |
| `sprite` | `x`, `y`, `direction`, `size`, `visible`, `costume`, `sayText`, `touchingEdge` |
| `variable` | 변수 값 (이름으로 지정) |
| `list` | 길이, 특정 항목 |
| `stage` | 현재 배경 |
| `clones` | 스프라이트의 복제본 수 |

비교 연산은 `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `between`, `contains`를 지원한다. 값에 `{ "ref": "initial" }`을 쓰면 액션 실행 전의 값과 비교한다. 숫자 비교에는 `tolerance`를 줄 수 있다.

**실행 흐름**

1. 에디터가 `grade` 메시지를 받으면 현재 작품을 sb3로 내보내 스냅샷을 만든다.
2. 정적 검사를 먼저 실행한다. 실패하면 동적 검사는 건너뛴다.
3. 동적 검사는 보이지 않는 채점용 실행 환경에 스냅샷을 불러와 실행한다. 학생이 작업 중인 에디터의 상태는 바뀌지 않는다. 채점용 환경은 필요할 때 만들고 채점이 끝나면 없애 메모리를 돌려준다.
4. 결과(`pass`, `fail`, `error`), 검사별 결과, 스냅샷을 본 사이트에 응답한다.
5. 본 사이트는 학생에게 통과 또는 실패만 보여주고 서버에 기록한다(5장). 검사별 결과는 개발 중 디버깅용으로만 쓰고 저장하지 않는다.

**안전장치**

- 동적 검사마다 `timeoutMs`(기본 5000)가 지나면 실행을 멈추고 실패로 처리한다.
- 난수를 쓰는 과제를 위해 `runs`(반복 실행 횟수)와 `passIf`(`all` 또는 `any`)를 지원한다.
- 채점 중 예외가 나면 실패가 아닌 "채점 오류"로 기록하고 학생에게 다시 시도하라고 안내한다.
- 채점용 실행 환경의 소리는 끈다.

**테스트**

`grader/`에는 규칙마다 통과 사례와 실패 사례의 프로젝트 JSON 픽스처로 단위 테스트를 작성한다(Vitest). 동적 검사는 샘플 튜토리얼의 정답 sb3와 오답 sb3로 브라우저 테스트(Playwright)를 작성한다.

## 8. 본 사이트 변경 사항

스키마 변경(신규 테이블과 추가 컬럼)은 `spec.md` §5의 ERD를 따르고, 이 문서에는 다시 적지 않는다.

**API**

경로는 본 사이트의 기존 규칙에 맞춘다. 아래는 필요한 동작이다.

| 동작 | 권한 | 내용 |
| --- | --- | --- |
| 작품 불러오기 | 학생 본인 | 저장본, 없으면 시작 프로젝트, 없으면 빈 응답 |
| 작품 저장 | 학생 본인 | sb3 업로드. 최신 저장본을 덮어씀 |
| 채점 규칙 받기 | 학생 본인 | 지금 풀 수 있는 스텝의 `checks`만 응답 |
| 채점 결과 기록 | 학생 본인 | 결과와 sb3를 받아 시도 횟수 증가, 통과 시 스텝 완료, 작품 저장 |
| 프로젝트 제출 | 학생 본인 | 새 버전과 썸네일 저장, 제목과 배움 노트 저장 |
| 설계하기 답 불러오기·저장 | 학생 본인 | 설계하기 스텝의 답(`DESIGN_NOTE`). 모두 채워야 스텝 완료 |
| 설계하기 답 열람 | 교사, 관리자 | 학생 상세 화면에서 |
| 영상 링크 등록 | 학생 본인, 교사, 관리자 | 유튜브 링크를 `PROJECT.media_url`에 등록 또는 교체 |
| 학생 작품 열람 | 교사, 관리자 | 제출 버전 목록과 파일, 작업 중인 저장본 |

공유 신청과 승인, 커뮤니티 목록, 링크로 여는 작품, 좋아요, 댓글, 닉네임, 보호자 동의, 요청에 의한 삭제의 API 동작과 서버 검증은 `spec.md` §3.7.1에 있다.

**서버 검증**

- 채점 규칙은 이전 스텝을 모두 통과한 학생에게 현재 스텝 것만 준다. 단원 조회 응답에는 `checks`를 넣지 않는다.
- 채점 결과를 기록할 때 이전 스텝을 모두 통과했는지 확인하고, 아니면 거부한다.
- 업로드는 sb3(zip) 형식인지와 크기(20MB 이하)를 확인한다.
- 작업 중인 저장본과 공개되지 않은 버전은 본인, 교사, 관리자만 읽을 수 있고, 쓰기는 본인만 가능하다.
- 영상 링크는 유튜브 주소(`youtube.com`, `youtu.be`)만 받는다.
- 버전을 정리할 때 공개 중인 버전, 신청 중인 버전, 학부모 리포트에 실린 버전은 지우지 않는다.

**리포트와 대시보드**

히트맵 합산, 잘한 점/보완할 점 분석 제외, 포트폴리오와 학부모 리포트의 표시 방식은 `spec.md` §3.5와 §3.6을 따른다.

## 9. 다국어

한국어와 영어 전환은 스크래치 학습 화면 안에서만 동작하고, 교안 내용과 에디터 블록 언어가 함께 바뀐다. 기본은 한국어다. 전환은 에디터에 이미 있는 언어 메뉴로 하고, 본 사이트 화면에는 전환 버튼을 두지 않는다.

- **교안 내용**: `LESSON_STEP.content`의 `{ "ko", "en" }`에서 현재 언어를 고른다. 영어 값이 없으면 한국어로 대체한다.
- **에디터**: 언어 메뉴에는 한국어와 영어만 남긴다. 학생이 언어를 바꾸면 에디터가 `localeChanged`로 본 사이트에 알린다. 다시 들어올 때는 본 사이트가 저장해 둔 언어를 `init`으로 전달한다.
- **학습 화면의 버튼과 안내 문구**: "확인", "다음", "통과했어요" 등 본 사이트 쪽 문구는 첫 버전에서 한국어만 둔다. 영어를 골라도 이 문구들은 한국어 그대로다.
- **선택 저장**: 본 사이트가 `localeChanged`를 받을 때 브라우저에 저장한다. DB 컬럼은 추가하지 않는다.

채점 규칙을 쓸 때 주의할 점이 있다. 블록 opcode는 언어와 무관하지만, 스프라이트 기본 이름과 변수 이름, 말하기 블록의 문자열은 언어나 학생에 따라 달라진다.

- 스프라이트는 가능한 한 이름 대신 `@first`, `@any`로 가리킨다.
- 변수 이름이나 문자열을 비교해야 하면 값에 `{ "ko": "점수", "en": "score" }`처럼 언어별 값을 주고, 둘 중 하나와 일치하면 통과로 본다.

## 10. 구현 단계

아래 8단계를 순서대로 진행하고, 단계가 끝날 때마다 완료 기준을 확인한 뒤 멈춰서 검토를 받는다. 0단계부터 3단계는 `scratch-studio` 저장소, 4단계부터 7단계는 본 사이트 저장소의 작업이다. 0단계 결과에 따라 3장과 4장이 바뀔 수 있으므로 건너뛰지 않는다.

1. **0단계: 에디터 검증** (`scratch-studio`)
   - TurboWarp scratch-gui를 빌드해 띄우고, 다른 출처의 시험용 페이지에서 iframe으로 넣어 `postMessage`로 통신한다.
   - sb3 불러오기와 내보내기, 프로젝트 JSON 읽기, 초록 깃발 실행, 키 입력 주입, 스프라이트 좌표 읽기, 언어 변경, 무대 화면 캡처를 각각 확인한다.
   - 에디터에 이미 있는 저장 버튼과 저장 상태 표시(저장 가능 설정)를 켤 수 있는지, 눌렀을 때 서버 대신 메시지를 보내게 할 수 있는지, 저장 실패일 때 "다시 시도"를 보여줄 수 있는지 확인한다. 기본 모양과 문구가 목업과 얼마나 다른지도 적는다.
   - 에디터의 언어 메뉴를 한국어와 영어로만 줄일 수 있는지, 학생이 언어를 바꿨을 때 그 사실을 메시지로 알릴 수 있는지 확인한다.
   - 실행 전용 화면(무대만)과 블록 보기 화면을 같은 빌드에서 전환할 수 있는지 확인한다.
   - 보이지 않는 두 번째 실행 환경에서 작품을 실행하고 없앨 수 있는지 확인한다.
   - 펜과 음악 확장 블록이 쓰인 작품이 그 실행 환경에서도 동작하고, 펜 그림과 음악 블록의 결과를 채점에서 확인할 방법이 있는지 확인한다. Lv.1의 "자동 연주 오르골"과 "우연이 그리는 그림"이 이 블록을 쓴다.
   - 스프라이트와 소리 라이브러리가 어느 서버에서 불러와지는지 확인한다.
   - 학원에서 가장 사양이 낮은 PC에서 로딩 시간과 채점 중 버벅임을 잰다.
   - 완료 기준: 위 항목을 시연하는 시험용 페이지와, 안 되는 항목 및 대안을 적은 `docs/spike.md`.
2. **1단계: 브리지** (`scratch-studio`)
   - 4장의 메시지 규약 전부, 세 가지 모드, `protocol.ts`, 출처 검증, `frame-ancestors`, 사용자 확장 기능 차단.
   - 완료 기준: 시험용 페이지에서 작품을 열고, 고치고, 내보내고, 모드를 바꿀 수 있다. 허용되지 않은 출처의 메시지는 무시된다.
3. **2단계: 정적 채점** (`scratch-studio`)
   - 7장의 정적 규칙 전부와 `anyOf`, 규칙별 단위 테스트.
   - 완료 기준: 규칙별 통과·실패 테스트가 모두 통과한다.
4. **3단계: 동적 채점** (`scratch-studio`)
   - 채점용 실행 환경, 액션과 확인 조건 전부, 제한 시간, 반복 실행, `grade` 메시지 연결.
   - 이 단계부터 샘플 단원(실제 수업의 첫 단원)의 내용이 필요하다(11장).
   - 완료 기준: 샘플 단원의 정답 sb3는 통과하고 오답 sb3는 실패하며, 무한 반복이 있는 작품도 제한 시간 안에 끝난다.
5. **4단계: 스키마와 가져오기** (본 사이트)
   - `spec.md` §5의 스키마 변경과 마이그레이션, 파일 저장소, 가져오기 스크립트, 샘플 단원 1개 작성. 샘플은 정적 검사와 동적 검사를 모두 쓰는 5스텝 이상으로 한다.
   - 완료 기준: 샘플 단원을 가져오고, 고쳐서 다시 가져와도 기존 진도가 유지된다.
6. **5단계: 학습 화면 연결** (본 사이트)
   - 스크래치 전용 학습 화면(교안 패널, 미니퀴즈, 설계하기, 프로젝트 제출 스텝), `ScratchStudioFrame`, 교안 블록 렌더링, "확인" 흐름, 스텝 잠금, 자동 저장, 이어서 하기, 언어 전환. 화면은 hi-fi 목업의 화면 15를 따른다.
   - 완료 기준: 학생 계정으로 샘플 단원을 끝까지 진행할 수 있고, 로그아웃했다가 들어와도 같은 작품과 같은 스텝에서 이어진다. 기존 튜토리얼 진행 화면의 코드와 다른 튜토리얼형 과목의 동작은 바뀌지 않는다.
7. **6단계: 제출과 작품 페이지** (본 사이트)
   - 프로젝트 제출(버전 이력, 썸네일, 제목), 작품 페이지(실행, 블록 보기, 버전 선택), 교사의 작품 열람(제출 버전과 작업 중인 저장본), 영상 링크 등록, 버전 10개 한도, 포트폴리오와 학부모 리포트 연결, 히트맵 합산, 교안 관리 화면의 읽기 전용 처리.
   - 완료 기준: 제출한 작품을 본인과 교사가 작품 페이지에서 실행할 수 있고, 로그인하지 않은 사람은 열 수 없다. 다시 제출하면 새 버전이 쌓이고 이전 버전도 열린다. 교사가 작업 중인 저장본을 열어 고쳐도 학생의 저장본은 바뀌지 않는다.
8. **7단계: 공유와 커뮤니티 페이지** (본 사이트)
   - 동작과 서버 검증은 `spec.md` §3.7과 §3.7.1이 기준이다. 아래는 이 단계에서 만드는 것의 목록이다.
   - 닉네임 설정(첫 로그인)과 교사의 닉네임 변경, 보호자 동의 표시, 공유 신청과 취소, 교사의 신청 목록과 승인·거절·내리기, 커뮤니티 페이지(로그인 필요), 작품 링크, 좋아요와 댓글, 금지어 거르기, 교사용 최근 댓글 목록, 관리자의 작품·댓글 삭제, 로그인 없는 접근의 응답 제한과 요청 빈도 제한, `noindex`.
   - 완료 기준: 보호자 동의가 표시되지 않은 학생은 공유 신청을 할 수 없다. 교사가 승인하기 전에는 작품이 커뮤니티 페이지에 보이지 않는다. 승인된 작품은 작품 링크로 로그인 없이 실행되지만 블록 보기, 좋아요, 댓글은 보이지 않고, 응답에 닉네임 외의 학생 정보가 없다. 교사가 내린 작품은 링크가 즉시 무효가 되고, 학생이 새 버전을 제출해야 다시 신청할 수 있다. 학생이 스스로 내린 버전은 같은 버전으로 다시 신청할 수 있다.

**작업 원칙**

- TurboWarp 포크의 코드는 가능한 한 고치지 않는다. 꼭 필요한 수정은 `scratch-studio`의 `PATCHES.md`에 이유와 함께 기록한다.
- 본 사이트 작업은 기존 코드의 구조와 규칙을 따른다. 스크래치 전용 학습 화면은 새로 만들고, 기존 튜토리얼 진행 화면은 고치지 않는다.
- 이 문서에 없는 기능은 추가하지 않는다. 필요해 보이면 먼저 제안한다.
- 이 문서와 실제 동작이 다르면 임의로 우회하지 말고 차이를 보고한다.

## 11. 미정 사항과 주의점

아래 항목 중 체크하지 않은 항목은 아직 정해지지 않았고, 표시한 단계 전에 결정이나 확인이 필요하다.

- [ ] 에디터를 올릴 서브도메인과 호스팅. 본 사이트의 호스팅과 함께 정한다. 출처는 본 사이트와 달라야 하고, `frame-ancestors`를 위해 HTTP 응답 헤더를 설정할 수 있어야 한다. 0단계는 로컬에서 진행한다. (1단계 전)
- [ ] 샘플 단원의 교안 내용. Lv.1의 첫 프로젝트 "보물 지도 탐험"을 교안 틀에 맞춰 만든다. 교안 틀과 스텝 3의 예시는 있고, 나머지 스텝, 그림, 정답 작품은 아직 없다. (3단계 전)
- [x] 스크래치 전용 학습 화면의 디자인 시안. hi-fi 목업에 화면 15로 추가되었다(2026-10-05). 주 버튼과 현재 스텝 점의 강조색은 사이트의 주황이 아니라 목업의 파랑(`#2F6FD6`)을 쓴다.
- [x] 제출한 뒤 다시 제출하는 경로. hi-fi 목업에 재제출 장면(`resubmit`, `resubmitted`)이 추가되어 5장에 반영했다(2026-10-05).
- [x] 저장 상태와 "저장하기" 버튼의 위치. 목업대로 에디터의 메뉴 바 안에 두고, 에디터가 그려서 메시지로 본 사이트와 주고받기로 했다(2026-10-05, 4장과 5장에 반영). 에디터에서 실제로 가능한지는 0단계에서 확인한다. "교안 열기"는 이후 목업에서 본 사이트 쪽의 접힌 띠로 옮겨져 에디터와 무관해졌다.
- [ ] 파일 저장소. 본 사이트에는 파일 업로드와 저장 기능이 아직 없다. sb3, 썸네일, 교안 이미지, 시작 프로젝트를 저장할 곳을 본 사이트의 호스팅과 함께 정한다. 영상은 유튜브 링크를 쓰므로 보관하지 않는다. (4단계 전)

아래는 결정했지만 학원이 운영 전에 준비해야 하는 것이다.

- 학원의 유튜브 채널 또는 영상을 올릴 계정. 학생과 교사에게 "일부 공개"로 올리도록 안내한다.
- 작품 공개 동의 서류와 댓글 금지어 목록은 `spec.md` §3.7.2에 있다.

**알고 가야 할 한계**

작품 공유, 닉네임, 댓글에 관한 한계는 `spec.md` §3.7.2에 있다.

- 로그인한 학생은 공개된 작품의 블록을 볼 수 있으므로, 같은 단원의 정답을 베낄 수 있다.
- 본 사이트를 비공개로 두는 것은 일반적인 라이선스 해석에 따른 판단이며 법률 확인을 거치지 않았다.
- 영상은 유튜브에 올라가므로 사이트의 접근 통제 밖에 있다. "일부 공개"여도 링크를 아는 사람은 볼 수 있고, 유튜브에서 영상이 지워지면 사이트에서도 보이지 않는다. 교안 영상에는 유튜브의 추천 영상이 붙을 수 있다.
- 채점이 학생 브라우저에서 실행되므로 채점 규칙이 브라우저에 드러나고, 요청을 조작하면 통과로 기록할 수 있다. 파이썬의 테스트케이스가 서버에만 있는 것과 다르다. 서버는 이전 스텝을 모두 통과했는지까지만 확인한다(8장).
- 스텝 단위 예외가 없고 힌트도 없으므로, 채점 규칙이 지나치게 엄격하면 학생이 그 스텝에서 멈춘다. 규칙은 느슨한 쪽으로 쓰고, 수업 전에 여러 가지 정답으로 시험한다. `spec.md`의 단원 수동 완료는 단원 전체를 넘기는 기능이라 스텝을 열어주지는 못한다.
- 작업 중인 저장본은 1개만 보관하므로, 학생이 작품을 망가뜨린 채 저장되면 되돌릴 수 없다. 제출한 버전이 있으면 그 시점으로는 돌아갈 수 있다.
- 인터넷이 끊기면 저장과 채점 기록이 되지 않는다. 화면에 저장 실패를 표시한다.
- 태블릿은 지원하지 않는다. 터치 조작과 좁은 화면에서의 동작은 확인하지 않는다.
- 사양이 낮은 기기에서는 동적 채점 중에 잠깐 버벅일 수 있다.
