# Lv.1-1 보물 지도 탐험 · 교사용 자료

학생 화면에 나오지 않는 내용이다. 교안 본문과 퀴즈는 `project/lv1/01-treasure-map/unit.json`에 있다. 시작 프로젝트와 그림·GIF는 `tools/01-treasure-map/build_media.py`로 다시 만든다.

## 1. 학습 목표와 개념 구분

**선수학습**: 없음. 스크래치를 처음 여는 단원이다.

**새로 배우는 개념**
- 이벤트: `깃발 클릭했을 때`, `키를 눌렀을 때`
- 순차: 블록이 위에서부터 차례로 실행된다
- 좌표: `x: y: (으)로 이동하기`, `x좌표를 ~만큼 바꾸기`, `y좌표를 ~만큼 바꾸기`, `x 좌표`·`y 좌표` 값, 가운데가 (0, 0), 왼쪽·아래는 음수, 무대는 가로 -240~240, 세로 -180~180

**정해진 블록 (개념은 뒤 단원에서 배움)**
- `탐험가에 닿았는가? 까지 기다리기`: 구성안의 새 개념(이벤트, 순차, 좌표)만으로는 "보물을 찾았다"를 알아낼 수 없어서 넣었다. 학생은 블록 그림대로 붙이고, "탐험가가 닿을 때까지 기다린다"까지만 이해하면 된다. 조건과 감지는 3번 '달리는 말 경주'에서 배운다.
- `(타이머)`: 필수 구현 "걸린 시간 표시"를 위해 쓴다. 스크래치 안의 초시계라고만 설명한다. 깃발을 누르면 스크래치가 타이머를 스스로 0으로 돌리므로(엔진에서 확인) 정답 코드에 `타이머 초기화`는 넣지 않고, s19 탐색에서 눌러 보기만 한다.
- `~초 동안 말하기`, `말하기`: 꾸미기와 걸린 시간에 쓴다. 소리와 모양 바꾸기는 2번·3번 단원의 새 개념이라 쓰지 않는다.
- `투명도 효과`: 확장 미션 E에서만 블록 그림대로 쓴다.

**관찰 가능한 목표**
1. 좌표를 보고 무대의 어느 쪽인지 고른다. (s04, s05, q1-1)
2. 방향키를 누르면 x나 y가 어떻게 바뀌는지 말한다. (s07, s09, s10, q1-2, q1-3, 설명 도전 2)
3. `이동하기`와 `바꾸기`의 차이를 예를 들어 말한다. (s08)
4. 보물이 쪽지 순서대로 옮겨 다니는 까닭을 순차로 설명한다. (s14, s15, q2-1, q2-2, q3-1, 설명 도전 1)
5. 깃발을 누르면 타이머가 0이 되어, 마지막 보물을 찾은 순간의 타이머가 걸린 시간이라는 것을 말한다. (s19, s20)
6. 깃발에서 처음 자리를 정하는 까닭을 말한다. (s06, q3-2, 설명 도전 3)
7. 자리를 정확히 말하려면 숫자 두 개가 필요하다는 것을 이야기와 잇는다. (s01, s02, s04, q3-3)

**개념 연결**: 이야기(s01~s03) → 좌표와 이동(s04~s12) → 순차와 보물 숨기기(s13~s20) → 완성 확인(s21)

**화면 둘러보기 (5분)**: 첫 단원이므로 s04 전에 화면을 직접 보여 준다. 스프라이트 고르기, 블록 끌어 붙이기, 블록 지우기(블록 꾸러미로 끌어다 놓기), 블록 클릭해서 실행하기, 숫자 칸 고치기를 보여 준다.

**자동 검사**: 동적 검사를 먼저 쓰고, 정적 검사는 새 블록이 나오는 스텝(s06 `x: y: 이동하기`, s15 `까지 기다리기`, s20 `타이머`)에만 둔다. s13은 블록이 새로 나오지 않고, 시작 프로젝트의 보물이 (120, -60)에 있어 동적 검사로 구분된다. s20은 "네 번째까지 찾았을 때는 아직 말하지 않는다"도 본다. 다섯 번째 `기다리기`를 빠뜨리면 네 번째를 찾자마자 시간을 말해 버리는데, 이 검사가 없으면 어느 스텝에서도 걸리지 않았다(7장).

**방향키 검사가 10을 요구하는 까닭**: s09와 s10은 한 번 누를 때 정확히 10만큼 움직이는지 본다(-170, -190, -110, -130). s15부터는 정해진 횟수로 방향키를 눌러 보물까지 가는 검사를 쓰기 때문에, 걸음 크기가 다르면 뒤 스텝이 모두 걸린다. 목표 문장에 "10만큼"을 넣었다.

야자수 (180, 120)은 설명 그림에 답이 있어서 표에 넣지 않았다. s01의 어림해 보기 답은 가로 5번째, 세로 3번째 타일이고, s02의 그림 보기 답은 C열 5번이다.

**s05의 숫자**: 무대 밖 좌표로 보내면 스크래치가 스프라이트를 무대 끝에 붙잡아 둔다. 엔진에서 (300, 0)은 (241, 0), (0, -250)은 (0, -193), (-400, 200)은 (-241, 185)에 멈췄다. 스프라이트가 조금 보이게 남기는 방식이라 좌표가 240, 180과 딱 맞지 않는다. 학생이 물으면 "끝에 걸려서 그림의 가운데가 끝 언저리에 있다"고 답한다.

**s08**: `x 좌표` 표시가 켜져 있어야 한다(s04 해 보기). 줄마다 가운데에서 다시 시작하지 않으면 두 번째 줄의 답이 달라진다.

**s14**: 깃발 없이 블록 묶음을 클릭해 실행한다. 순서 3은 (0, 0)으로 가는 것이 보이지 않을 만큼 빨라서 q2-2와 이어진다.

**s19**: 해 보기 3이 핵심이다. 깃발만 눌러도 타이머가 0이 되는 것을 학생이 직접 본다. 그래서 정답 코드에 `타이머 초기화`가 없다. "그럼 `타이머 초기화`는 언제 써요?"라고 물으면 "깃발 말고 다른 때(예: 미션 C의 `b` 키로 다시 시작할 때) 0으로 돌리고 싶을 때"라고 답한다.

## 3. 재시작 점검

깃발을 누르면 다음이 처음 상태로 돌아와야 한다.

| 대상 | 처음 상태 | 맡는 블록 |
| --- | --- | --- |
| 탐험가 자리 | 배 (-180, -120) | 탐험가 깃발 스크립트의 `x: -180 y: -120 이동하기` |
| 보물 자리 | 첫 자리 (-60, -60) | 보물 깃발 스크립트의 첫 이동 블록 |
| 보물 스크립트 | 첫 `기다리기`에서 대기 | 깃발을 누르면 스크립트가 처음부터 다시 시작됨 |
| 타이머 | 0 | 스크래치가 깃발을 누를 때 스스로 0으로 돌림 (엔진에서 확인) |
| 말풍선 | 지워짐 | 스크래치가 깃발을 누를 때 자동으로 지움 |

**탐험가가 첫 자리에 서 있을 때 다시 시작**: 두 스크립트가 같은 순간에 시작되므로, 탐험가가 배로 가기 전에 보물이 첫 자리에서 탐험가에 닿아 곧바로 넘어갈까 걱정할 수 있다. 엔진에서 탐험가를 (-60, -60)에 세워 두고 깃발을 눌러 보니 일어나지 않았다. 탐험가는 배로, 보물은 첫 자리로 갔다. "찾았다!"를 말하는 도중이나 두 번째 보물로 가는 도중에 깃발을 눌러도 탐험가, 보물, 타이머가 모두 처음으로 돌아갔다(7장).

출발 인사(s11), 좌표 말하기(s12), 찾았다(s18)는 꾸미기라 없어도 게임은 동작한다. "찾았다!"는 첫 번째부터 네 번째 보물에만 붙인다. 다섯 번째 보물은 찾는 순간 곧바로 시간을 말해야 걸린 시간이 정확하다.

## 5. 무대와 좌표

| 대상 | 좌표 | 비고 |
| --- | --- | --- |
| 탐험가 출발 (배) | (-180, -120) | 시작 프로젝트에서는 (0, 0)에 있다 |
| 보물 1 | (-60, -60) | 시작 프로젝트에서는 보물이 (120, -60)에 있다 |
| 보물 2 | (-120, 60) |  |
| 보물 3 | (60, 120) |  |
| 보물 4 | (120, 0) |  |
| 보물 5 | (0, -120) |  |
| 동굴 / 야자수 / 해골 바위 | (-180, 120) / (180, 120) / (180, -120) | 배경 그림. 네 귀퉁이가 부호 네 가지(+/-)를 하나씩 맡는다 |

배경 지도는 60마다 격자선이 있고, 가운데 두 줄(x = 0, y = 0)이 진하다. 보물 자리는 모두 격자선이 만나는 곳이다.

**채점 경로**: 동적 검사는 배에서 출발해 가로로 먼저, 세로로 나중에 방향키를 눌러 보물 자리로 간다. 한 번 누를 때마다 50ms 누르고 70ms 기다린다.

| 구간 | 누르는 키 | 도착 |
| --- | --- | --- |
| 배 → 1 | → 12번, ↑ 6번 | (-60, -60) |
| 1 → 2 | ← 6번, ↑ 12번 | (-120, 60) |
| 2 → 3 | → 18번, ↑ 6번 | (60, 120) |
| 3 → 4 | → 6번, ↓ 12번 | (120, 0) |
| 4 → 5 | ← 12번, ↓ 12번 | (0, -120) |

각 구간의 가로 이동 줄은 그 구간의 보물과 60 이상 떨어져 있어서, 세로로 올라가거나 내려갈 때 처음 닿는다. 보물이 다음 자리로 옮겨 간 뒤에도 탐험가와 60 이상 떨어져 있어서 한 번에 두 자리를 건너뛰지 않는다. 보물 자리를 바꾸면 이 조건을 다시 확인한다.

**s18 이후의 시간**: "찾았다!"를 말하는 1초 동안 보물은 옛 자리에 머문다. 채점 경로는 한 구간이 18번 이상(2초 이상)이라, 보물이 다음 자리에 먼저 도착하고 탐험가가 나중에 온다. s15~s17은 이 1초를 넘기도록 경로 끝에서 1초를 더 기다린 뒤 보물 자리를 본다. 다섯 번째 보물은 곧바로 시간을 말하므로 s20, s21은 짧게 기다린 뒤 말풍선을 본다.

### 그 밖의 오개념

- **음수를 "없는 수"로 생각함**: 4학년은 음수를 학교에서 배우지 않았다. "가운데보다 왼쪽(아래)에 있다는 표시"로만 설명한다. 수직선을 그려 -60에서 오른쪽으로 세 칸 가면 -30이 되는 것을 보여 준다(q1-2).
- **x와 y를 바꿔 읽음**: (-120, 60)을 "위로 120"으로 읽는다. "x가 먼저, 가로가 먼저"라고 짚는다. 지도의 x 표시와 y 표시를 가리키게 한다.
- **`이동하기`와 `바꾸기` 혼동**: 오른쪽 화살표에 `x: 10 y: 0 이동하기`를 붙이면, 엔진에서 탐험가가 (10, 0)으로 순간 이동한 뒤 몇 번을 더 눌러도 그 자리에 있었다. `x좌표를 바꾸기`는 지금 자리에서 그만큼 더 간다. s08 표를 다시 보게 한다. s09에서 걸린다.
- **키가 안 먹음**: 교안 패널을 누른 뒤에는 키 입력이 에디터로 가지 않는다. 무대를 한 번 클릭하게 한다(s09 안내에 있음).
- **스페이스가 두 군데**: 미션 C를 스페이스 키로 만들면 좌표 말하기(s12)와 겹친다. 엔진에서 스페이스를 누르자 탐험가가 배로 순간 이동하면서, 이동하기 **전**의 x 좌표(-120)를 말했다. 학생은 "배에 있는데 좌표가 이상해요"라고 한다. 한 키에 스크립트가 둘이면 둘 다 실행된다는 것을 보여 주고 `b` 키로 바꾸게 한다. 교안은 처음부터 `b` 키를 쓰게 했다.
- **보물 스크립트를 탐험가에 만듦**: 스프라이트를 고르지 않고 탐험가에 보물 스크립트를 만들면, 엔진에서 깃발을 누르자 **탐험가가** 첫 보물 자리 (-60, -60)으로 순간 이동하고 보물은 시작 자리 (120, -60)에 그대로 있었다. "탐험가가 보물 자리로 날아가요"라고 하면 이것이다. 스프라이트 목록에서 무엇이 골라져 있는지 먼저 보게 한다. s13에서 걸린다.
- **다섯 번째 자리 뒤에 기다리기를 빠뜨림**: 엔진에서 네 번째 보물을 찾자 보물이 다섯 번째 자리로 가면서 곧바로 시간을 말했다. 학생은 "다섯 번째를 안 찾았는데 끝났어요"라고 한다. s17 안내에 적어 두었고, s20에서 걸린다.

퀴즈 스텝마다 3문항을 화면에 둔다. 틀리면 틀린 문항을 따로 표시하지 않고, 그 문항 아래에 노란 칸으로 힌트를 보여 준다. 통과하면 모든 문항에 해설이 나온다.

| --- | --- | --- | --- |
| q1-1 | 왼쪽 위 | x가 -120이라 왼쪽, y가 60이라 위예요. | x가 음수면 가운데보다 왼쪽일까요, 오른쪽일까요? y가 0보다 크면요? |

| q1-3 | x좌표를 -10만큼 바꾸기 | 왼쪽은 가로로 오른쪽의 반대예요. 그래서 x를 -10만큼 바꿔요. | 왼쪽은 가로 방향이에요. 가로로 움직이는 것은 x와 y 중 무엇인가요? |

| q2-2 | (-60, -60) | (-120, 60)으로 갔다가 눈 깜짝할 새 (-60, -60)으로 가서 기다려요. | `기다리기` 바로 앞에 실행되는 블록은 무엇인가요? |
| q2-3 | 2번 | 첫 자리에서 한 번, 두 번째 자리에서 한 번 찾아서 세 번째 자리로 왔어요. | 첫 자리에서 세 번째 자리까지 몇 번 옮겨 갔나요? |

| q3-2 | 매번 같은 자리에서 출발해야 시간을 비교할 수 있어서 | 출발점이 매번 달라지면 걸린 시간을 비교할 수 없어요. | 깃발 스크립트가 없으면 두 번째 게임은 어디에서 시작할까요? |
| q3-3 | 2개 | 가로(x) 하나, 세로(y) 하나면 돼요. | 천장의 파리는 가로로 몇 칸, 세로로 몇 칸으로 말했어요. |

**수업 중에 말로 물을 질문** (화면에 넣지 않음)
- 무대 맨 오른쪽 위 귀퉁이의 좌표는? (240, 180). 맨 왼쪽 아래는? (-240, -180)
- 탐험가가 (0, 0)에 있을 때 위쪽 화살표를 5번 누르면? (0, 50)
- 깃발을 안 누르고 방향키만으로 다시 하면 걸린 시간이 맞을까? 맞지 않다. 타이머는 깃발을 누를 때 0이 되기 때문이다.
- "찾았다!"를 말하는 1초가 걸린 시간에 들어갈까? 들어간다. 그동안에도 탐험가는 움직일 수 있으니 기다리지 말고 다음 보물로 가면 된다.

탐험가 도전(시간)과 설명 도전(이해)은 따로 확인한다. 도전 시간 기준(60초, 40초, 25초)은 미리보기 GIF의 움직임으로 어림한 값이다. 엔진에서 채점 경로(키를 0.12초마다 한 번)는 약 16초, 로봇(1초 미끄러지기)은 약 5초였다. 첫 수업에서 실제 기록을 보고 고친다.

**이 결과로 고친 것**
- s15, s16, s17: "찾았다!"(s18)를 넣은 정답이 떨어졌다. 보물이 1초 동안 옛 자리에 머무는데 검사가 그 전에 위치를 봤기 때문이다. 세 검사 끝에 1초 기다림을 더했다.
- s11: 인사 블록을 이동 블록 위에 붙이면 s11은 통과하고 뒤 스텝들이 떨어졌다. 검사에 "말하는 동안 탐험가가 배에 있는지"를 더하고, 안내에 "이동 블록 아래에" 붙이라는 문장을 넣었다.
- s19: 깃발이 타이머를 스스로 0으로 돌려서 `타이머 초기화`의 효과를 학생이 볼 수 없었다. 만들기 스텝을 "탐색: 타이머 살펴보기"로 바꾸고 정답 코드에서 `타이머 초기화`를 뺐다.
- s20: 시간을 말하기 전에 "찾았다!"와 "모두 찾았어요"를 말해 걸린 시간이 3초 길게 나왔다. 다섯 번째 보물을 찾으면 곧바로 시간을 말하게 바꿨다. 또 다섯 번째 `기다리기`를 빠뜨린 작품이 모든 검사를 통과해서, "네 번째까지 찾았을 때는 아직 말하지 않는다" 검사를 더했다.
- 강사용 안내서: 다시 시작할 때의 경쟁(3장), 로봇 시간과 오개념 작품의 실제 동작(6장)을 엔진 결과대로 고쳤다.

**실행하지 못한 것**
- 키를 꾹 누를 때의 반복 입력: 운영체제가 만드는 입력이라 엔진 시험으로는 흉내 낼 수 없다.
- 확장 미션 A~D (E만 확인).
- 실제 스크래치 에디터 화면의 블록 이름(한국어·영어)이 교안 글과 같은지.
- 배경 그림(PNG, 2배 해상도)이 에디터에서 흐리지 않게 보이는지.
- 실제 채점 엔진(아직 없음)이 `eq ""`, `ne ""`, `contains`를 이 도구와 같은 뜻으로 판정하는지.

## 9. 스키마 메모

새 필드는 추가하지 않았다. 스텝은 기존 필드(`key`, `title`, `content`, `checks`, `kind`), 퀴즈 문항은 기존 필드(`key`, `question`, `blocks`, `options`, `answer`, `hint`, `explain`)만 쓴다. 자동 검사도 기존 규칙(`hasBlock`, `underHat`, 동적 검사, `record`)만 쓴다. 입력 표의 숫자 칸(`kind: number`)은 해적선 대포에는 없던 쓰임이지만 학습 화면이 이미 지원한다.
