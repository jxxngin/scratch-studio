# Lv.1-1 보물 지도 탐험 · 교사용 자료

학생 화면에 나오지 않는 내용이다. 교안 본문과 퀴즈는 `project/lv1/01-treasure-map/unit.json`에 있다. 시작 프로젝트와 그림·GIF는 `tools/01-treasure-map/build_media.py`로 다시 만든다.

## 1. 학습 목표와 개념 구분

**선수학습**: 없음. 스크래치를 처음 여는 단원이다.

**새로 배우는 개념**
- 이벤트: `깃발 클릭했을 때`, `키를 눌렀을 때`
- 순차: 블록이 위에서부터 차례로 실행된다
- 좌표: `x: y: (으)로 이동하기`, `x좌표를 ~만큼 바꾸기`, `y좌표를 ~만큼 바꾸기`, 가운데가 (0, 0), 왼쪽·아래는 음수

**정해진 블록 (개념은 뒤 단원에서 배움)**
- `탐험가에 닿았는가? 까지 기다리기`: 구성안의 새 개념(이벤트, 순차, 좌표)만으로는 "보물을 찾았다"를 알아낼 수 없어서 넣었다. 학생은 블록 그림대로 붙이고, "탐험가가 닿을 때까지 기다린다"까지만 이해하면 된다. 조건과 감지는 3번 '달리는 말 경주'에서 배운다.
- `타이머 초기화`, `(타이머)`: 필수 구현 "걸린 시간 표시"를 위해 쓴다. 스크래치 안의 초시계라고만 설명한다.
- `말하기`: 꾸미기와 걸린 시간에 쓴다.

**관찰 가능한 목표**
1. 좌표를 보고 무대의 어느 쪽인지 고른다. (s03, q1-1)
2. 방향키를 누르면 x나 y가 어떻게 바뀌는지 말한다. (s05, s06, q1-2, q1-3, 설명 도전 2)
3. 보물이 쪽지 순서대로 옮겨 다니는 까닭을 순차로 설명한다. (s09, q2-1, q2-2, q3-1, 설명 도전 1)
4. 깃발에서 처음 자리를 정하는 까닭을 말한다. (s04, q3-2, 설명 도전 3)
5. 자리를 정확히 말하려면 숫자 두 개가 필요하다는 것을 이야기와 잇는다. (s01, s03, q3-3)

**개념 연결**: 이야기(s01~s02) → 좌표와 이동(s03~s07) → 보물 숨기기와 순차(s08~s11) → 완성 확인(s12)

**수업 운영**: 첫 단원이므로 s03 전에 5분 동안 화면을 직접 보여 준다. 스프라이트 고르기, 블록 끌어 붙이기, 블록 지우기(블록 꾸러미로 끌어다 놓기), 블록 클릭해서 실행하기, 숫자 칸 고치기를 보여 준다.

**자동 검사**: 동적 검사를 먼저 쓰고, 정적 검사는 새 블록이 나오는 스텝(s04 `x: y: 이동하기`, s09 `까지 기다리기`, s11 `타이머`, `타이머 초기화`)에만 둔다. s08은 블록이 새로 나오지 않고, 시작 프로젝트의 보물이 (120, -60)에 있어 동적 검사로 구분된다.

**방향키 검사가 10을 요구하는 까닭**: s06은 한 번 누를 때 정확히 10만큼 움직이는지 본다(-170, -190, -110, -130). s09부터는 정해진 횟수로 방향키를 눌러 보물까지 가는 검사를 쓰기 때문에, 걸음 크기가 다르면 뒤 스텝이 모두 걸린다. 목표 문장에 "10만큼"을 넣었다.

**입력 표**: s03과 s05는 "내 예상"을 고른 뒤 블록을 눌러 보고 "해 보니"에서 [맞았어요] 또는 [달랐어요]를 누른다. 최종 값이 모두 맞아야 통과다. s12의 기록표(걸린 시간)는 채점하지 않는다. 세 판의 시간을 비교하게 하고, 빨라진 까닭을 말하게 하면 좋다.

| s03 | (180, -120) | 해골 바위 |
| s03 | (-180, -120) | 배 |

## 3. 재시작 점검

깃발을 누르면 다음이 처음 상태로 돌아와야 한다.

| 대상 | 처음 상태 | 맡는 블록 |
| --- | --- | --- |
| 탐험가 자리 | 배 (-180, -120) | 탐험가 깃발 스크립트의 `x: -180 y: -120 이동하기` |
| 보물 자리 | 첫 자리 (-60, -60) | 보물 깃발 스크립트의 첫 이동 블록 |
| 보물 스크립트 | 첫 `기다리기`에서 대기 | 깃발을 누르면 스크립트가 처음부터 다시 시작됨 |
| 타이머 | 0 | 보물 깃발 스크립트의 `타이머 초기화` (스크래치도 깃발을 누를 때 타이머를 0으로 돌린다) |
| 말풍선 | 지워짐 | 스크래치가 깃발을 누를 때 자동으로 지움 |

**주의**: 탐험가가 (-60, -60) 가까이에 서 있는 채로 깃발을 누르면, 탐험가가 배로 가기 전에 보물이 첫 자리에서 탐험가에 닿아 곧바로 두 번째 자리로 갈 수 있다(같은 순간에 두 스크립트가 시작되기 때문). 보통은 게임이 다섯 번째 자리 (0, -120)에서 끝나므로 생기지 않는다. 학생이 "보물이 처음부터 두 번째 자리에 있어요"라고 하면 이것이다. 깃발을 한 번 더 누르면 된다.

## 5. 무대와 좌표

| 대상 | 좌표 | 비고 |
| --- | --- | --- |
| 탐험가 출발 (배) | (-180, -120) | 시작 프로젝트에서는 (0, 0)에 있다 |
| 보물 1 | (-60, -60) | 시작 프로젝트에서는 보물이 (120, -60)에 있다 |
| 보물 2 | (-120, 60) |  |
| 보물 3 | (60, 120) |  |
| 보물 4 | (120, 0) |  |
| 보물 5 | (0, -120) |  |
| 동굴 / 야자수 / 해골 바위 | (-180, 120) / (180, 120) / (180, -120) | 배경 그림. 네 귀퉁이가 부호 네 가지(+/-)를 하나씩 맡는다 |

배경 지도는 60마다 격자선이 있고, 가운데 두 줄(x = 0, y = 0)이 진하다. 보물 자리는 모두 격자선이 만나는 곳이다.

**채점 경로**: 동적 검사는 배에서 출발해 가로로 먼저, 세로로 나중에 방향키를 눌러 보물 자리로 간다. 한 번 누를 때마다 50ms 누르고 70ms 기다린다.

| 구간 | 누르는 키 | 도착 |
| --- | --- | --- |
| 배 → 1 | → 12번, ↑ 6번 | (-60, -60) |
| 1 → 2 | ← 6번, ↑ 12번 | (-120, 60) |
| 2 → 3 | → 18번, ↑ 6번 | (60, 120) |
| 3 → 4 | → 6번, ↓ 12번 | (120, 0) |
| 4 → 5 | ← 12번, ↓ 12번 | (0, -120) |

각 구간의 가로 이동 줄은 그 구간의 보물과 60 이상 떨어져 있어서, 세로로 올라가거나 내려갈 때 처음 닿는다. 보물이 다음 자리로 옮겨 간 뒤에도 탐험가와 60 이상 떨어져 있어서 한 번에 두 자리를 건너뛰지 않는다. 보물 자리를 바꾸면 이 조건을 다시 확인한다.

### 설명 도전(s12)과 생각해 보기 질문

| 질문 | 예상 답변 | 대표 오개념과 도움말 |
| --- | --- | --- |
| 보물이 쪽지 순서대로 옮겨 다니는 까닭 | 보물 스크립트에 쪽지 순서대로 블록을 쌓았고, 블록은 위에서부터 차례로 실행된다 | "스크래치가 알아서 다음 자리를 찾는다". 스크립트를 위에서부터 손가락으로 짚으며 따라가게 한다 |
| 왼쪽 화살표에서 x를 -10만큼 바꾸는 까닭 | 왼쪽으로 가면 x가 작아지니까 | "왼쪽은 -x 블록이 따로 있다". s05 표의 `x좌표를 -30만큼` 줄을 다시 보게 한다 |
| 깃발에서 탐험가를 배로 보내는 까닭 | 매번 같은 자리에서 출발해야 시간을 비교할 수 있다 | "깃발을 누르면 저절로 처음 자리로 간다". 깃발 블록을 빼고 두 번 해 보게 한다 |
| 키를 꾹 누르고 있으면? (s06 도전) | 처음에 한 번 움직이고 잠깐 뒤 계속 움직인다 | 키보드의 반복 입력 때문이다. 스크래치가 블록을 여러 번 실행한다 |
| 순서를 지키지 않고 세 번째 자리로 먼저 가면? (s10 도전) | 아무 일도 없다. 보물은 아직 앞 자리에서 기다린다 | "보물이 거기서도 나온다". 보물은 한 번에 한 자리에만 있다 |
| 3번과 4번 자리를 바꿔 쌓으면? (s14) | 로봇이 4번 자리에 먼저 가도 보물은 아직 3번에서 기다린다. 그다음 3번에서 찾으면 보물은 4번으로 가지만, 로봇은 이미 4번을 지나서 남은 보물을 다 찾지 못하고 끝난다 | "어느 순서로 가도 다 찾는다". 순서가 바뀌면 결과가 바뀐다는 것이 순차의 핵심이다 |
| 함정이 한 번만 걸리는 까닭 (미션 D) | 기다리기가 한 번 끝나면 스크립트도 끝나서 다시 확인하지 않는다 | 반복은 2번 '모스부호 송신기'에서 배운다. 지금은 "한 번 기다리고 끝난다"까지만 |

### 그 밖의 오개념

- **음수를 "없는 수"로 생각함**: 4학년은 음수를 학교에서 배우지 않았다. "가운데보다 왼쪽(아래)에 있다는 표시"로만 설명한다. 수직선을 그려 -60에서 오른쪽으로 세 칸 가면 -30이 되는 것을 보여 준다(q1-2).
- **x와 y를 바꿔 읽음**: (−120, 60)을 "위로 120"으로 읽는다. "x가 먼저, 가로가 먼저"라고 짚는다. 지도의 x 표시와 y 표시를 가리키게 한다.
- **`이동하기`와 `바꾸기` 혼동**: `x: y: 이동하기`는 그 자리로 가고, `x좌표를 바꾸기`는 지금 자리에서 그만큼 더 간다. s03과 s05를 비교하게 한다.
- **키가 안 먹음**: 교안 패널을 누른 뒤에는 키 입력이 에디터로 가지 않는다. 무대를 한 번 클릭하게 한다(s06 안내에 있음).
- **보물 대신 탐험가에 기다리기를 넣음**: 탐험가의 깃발 스크립트에 `기다리기`를 넣으면 보물이 움직이지 않는다. 스프라이트 목록에서 무엇이 골라져 있는지 먼저 보게 한다.

### 퀴즈 정답과 의도

퀴즈 스텝마다 3문항을 화면에 둔다. 틀리면 틀린 문항을 따로 표시하지 않고, 그 문항 아래에 노란 칸으로 힌트를 보여 준다. 통과하면 모든 문항에 해설이 나온다.

| 문항 | 정답 | 해설(통과하면 나옴) | 힌트(틀리면 그 문항 아래에 나옴) |
| --- | --- | --- | --- |
| q1-1 | 왼쪽 위 | x가 -120이라 왼쪽, y가 60이라 위예요. | x가 음수면 가운데보다 왼쪽일까요, 오른쪽일까요? y가 0보다 크면요? |
| q1-2 | -30 | -60, -50, -40, -30. 오른쪽으로 갈수록 0에 가까워져요. | 오른쪽 키를 한 번 누르면 x가 10 커져요. -60에서 하나씩 세어 보세요. |
| q1-3 | x좌표를 -10만큼 바꾸기 | 왼쪽은 가로로 오른쪽의 반대예요. 그래서 x를 -10만큼 바꿔요. | 왼쪽은 가로 방향이에요. 가로로 움직이는 것은 x와 y 중 무엇인가요? |
| q2-1 | (-60, -60)에서 기다려요 | 탐험가가 닿을 때까지 기다리는 동안 아래 블록은 실행되지 않아요. | `까지 기다리기` 아래의 블록은 언제 실행될까요? |
| q2-2 | (-60, -60) | (-120, 60)으로 갔다가 눈 깜짝할 새 (-60, -60)으로 가서 기다려요. | `기다리기` 바로 앞에 실행되는 블록은 무엇인가요? |
| q2-3 | 2번 | 첫 자리에서 한 번, 두 번째 자리에서 한 번 찾아서 세 번째 자리로 왔어요. | 첫 자리에서 세 번째 자리까지 몇 번 옮겨 갔나요? |
| q3-1 | 블록이 위에서부터 차례로 실행되어서 | 쪽지 순서대로 쌓은 블록이 차례로 실행돼요. 이것이 순차예요. | 블록 순서와 쪽지 순서를 나란히 놓고 비교해 보세요. |
| q3-2 | 매번 같은 자리에서 출발해야 시간을 비교할 수 있어서 | 출발점이 매번 달라지면 걸린 시간을 비교할 수 없어요. | 깃발 스크립트가 없으면 두 번째 게임은 어디에서 시작할까요? |
| q3-3 | 2개 | 가로(x) 하나, 세로(y) 하나면 돼요. | 천장의 파리는 가로로 몇 칸, 세로로 몇 칸으로 말했어요. |

**수업 중에 말로 물을 질문** (화면에 넣지 않음)
- 무대 맨 오른쪽 위 귀퉁이의 좌표는? (240, 180). 맨 왼쪽 아래는? (-240, -180)
- 탐험가가 (0, 0)에 있을 때 위쪽 화살표를 5번 누르면? (0, 50)
- `타이머 초기화`를 맨 아래로 옮기면 무엇이 달라질까? 시간을 말한 뒤에 0이 되므로, 말하는 시간 자체는 같다. 깃발을 누를 때 스크래치가 이미 타이머를 0으로 돌리기 때문이다. 그래도 "시작할 때 0으로"를 보여 주려고 맨 위에 둔다.

포수 도전처럼 탐험가 도전(시간)과 설명 도전(이해)은 따로 확인한다. 도전 시간 기준(60초, 40초, 25초)은 미리보기 GIF의 움직임으로 어림한 값이라 첫 수업에서 실제 기록을 보고 고친다.

## 7. 검증 기록 (2026-10-16)

**확인한 것**
- `unit.json`: 스텝 키와 목차(`chapters`)의 스텝 순서가 같은지, 모든 그림 파일이 있는지, 모든 글에 영어 값이 있는지 스크립트로 확인했다.
- 채점 경로: 5장의 구간마다 가로 이동 줄과 보물 사이가 60 이상인지 좌표로 계산했다(탐험가 그림 높이 48, 보물 그림 높이 28).
- 미리보기 GIF: 같은 경로로 그렸다. GIF 속 판정은 어림이다(가로세로 26 이내).

**실행하지 못한 것**
- 스크래치 엔진에서 정답 코드를 돌려 보지 않았다. 특히 `닿았는가?`는 그림의 실제 겹침으로 판정하므로, 보물이 정확히 어느 걸음에서 옮겨 가는지는 엔진에서 확인해야 한다.
- 채점 엔진이 아직 없어서 `checks`를 채점기로 돌리지 않았다.
- `sayText`의 `ne ""` 비교와 `underHat`의 `sensing_resettimer` 검사가 채점 엔진에서 뜻대로 동작하는지 확인하지 않았다.
- 70ms 간격의 연속 키 입력이 모두 스크립트를 한 번씩 실행시키는지(앞 실행이 끝나기 전에 다음 입력이 오면 무시됨) 엔진에서 확인하지 않았다. 실패하면 간격을 해적선 대포처럼 120ms로 늘린다.
- 배경 그림(PNG, 2배 해상도)이 에디터에서 흐리지 않게 보이는지 확인하지 않았다.

학생 본문은 파리 이야기를 "전해 오는 이야기"로, 1637년 책은 사실로 나눠 썼다. 학생이 "진짜예요?"라고 물으면 "이야기는 확실하지 않지만, 숫자 두 개로 자리를 나타내는 방법을 책에 쓴 것은 사실"이라고 답한다. 지도 앱의 위도·경도는 일반 상식으로 넣었다.

이야기 그림(천장의 파리, 해적의 쪽지)은 모두 직접 그린 것이라 출처 표기가 필요 없다.

## 9. 스키마 메모

새 필드는 추가하지 않았다. 스텝은 기존 필드(`key`, `title`, `content`, `checks`, `kind`), 퀴즈 문항은 기존 필드(`key`, `question`, `blocks`, `options`, `answer`, `hint`, `explain`)만 쓴다. 자동 검사도 기존 규칙(`hasBlock`, `underHat`, 동적 검사, `record`)만 쓴다.
