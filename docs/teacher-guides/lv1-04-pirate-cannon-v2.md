# Lv.1-4 해적선 대포 · 교사용 자료 (합친 교안)

학생 화면에 나오지 않는 내용이다. 교안 본문과 퀴즈는 `project/lv1/04-pirate-cannon-v2/unit.json`에 있다.

## 1. 학습 목표와 개념 구분

**선수학습**: 이벤트(깃발, 키), 반복(횟수), 좌표(x, y). 조건(`만약`)과 감지(`닿았는가?`)는 앞 단원에서 만났지만, 이 단원에서 다시 단계별로 연습한다.

**새로 배우는 개념**
- 방향: 스크래치 방향 숫자(위 0, 오른쪽 90, 아래 180, 왼쪽 -90)
- 변수: 만들기, `정하기`와 `바꾸기`, 숫자 칸에 변수 넣기, 여러 스프라이트가 같은 변수 쓰기

**관찰 가능한 목표**
1. 원하는 쪽을 보게 하는 방향 숫자를 고른다. (s04, s05, q1)
2. `정하기`와 `바꾸기`의 차이를 예를 들어 말한다. (s07, q1-3)
3. 포탄이 대포와 같은 쪽으로 날아가는 까닭을 `각도` 변수로 설명한다. (s12, q3-2, q6-4, 설명 도전 1)
4. 명중 확인을 반복 안에 넣어야 하는 까닭을 설명한다. (s18b, q5-3, 설명 도전 2)
5. 깃발에서 변수를 처음 값으로 정하는 까닭을 말한다. (s23, q6-3, 설명 도전 3)
6. 과녁을 보고 각도를 어림하고, 빗나간 방향을 보고 다음 각도를 고친다. (s24 기록표)

**개념 연결**: 방향과 변수(s04~s07) → 조준(s08~s11) → 발사(s12~s17) → 명중 판정(s18~s19) → 과녁 이동(s20~s22) → 기록과 평가(s23~s24)

자동 검사는 실행 결과를 보는 동적 검사를 먼저 쓰고, 정적 검사(블록 검사)는 새 블록이 나오는 스텝(s05, s06, s08, s12, s20)에만 둔다. s18만 예외로, 과녁이 처음부터 첫 자리에 있어 동적 검사로 구분되지 않으므로 깃발 아래의 이동 블록을 정적으로 확인한다.

s24는 포수 시험 기록표를 그대로 두고 완성 확인을 더한 스텝이다. 게임 전체(과녁 3개를 맞히고 사라짐)와 깃발을 다시 눌렀을 때 처음 상태로 돌아오는지를 확인한다. 꾸미기나 실험에서 바꾼 것이 남아 있으면 여기서 걸린다.

**입력 표**: s04-direction, s07-variable-play, s16-range, s24-gunner-test의 표는 학생이 직접 적는 입력 표다. s04, s07, s16은 "내 예상"을 적은 뒤 블록을 눌러 보고 "해 보니" 칸에서 [맞았어요] 또는 [달랐어요]를 누른다. 달랐을 때만 실제 값을 고른다(같은 값을 두 번 적지 않게). 예상을 적어야 "해 보니" 칸이 열린다. 채점은 최종 값(맞았으면 예상, 달랐으면 실제 값)이 모두 맞아야 통과다. 예상이 틀린 것만으로는 실패하지 않는다. s24 기록표는 채점하지 않는다. 예상과 결과가 다른 줄을 골라 왜 달랐는지 말하게 하면 좋다.

## 3. 재시작 점검

깃발을 누르면 다음이 처음 상태로 돌아와야 한다.

| 대상 | 처음 상태 | 맡는 블록 |
| --- | --- | --- |
| `각도` | 90 | 대포 깃발 스크립트 |
| `발사` | 0 | 대포 깃발 스크립트 |
| `명중` | 0 | 과녁 깃발 스크립트 |
| 대포 방향 | 90 | 대포 깃발 스크립트의 `(각도) 도 방향 보기` |
| 대포 모양 | 대포 | s15를 했다면 깃발 스크립트의 `모양을 대포로` |
| 포탄 | 숨김 | 포탄 깃발 스크립트 |
| 과녁 | 첫 자리, 보임, 과녁 모양 | 과녁 깃발 스크립트의 이동, `보이기`, `모양을 과녁으로` |
| 말풍선 | 지워짐 | 스크래치가 깃발을 누를 때 자동으로 지움 |

## 6. 예상 답변과 대표 오개념

### 설명 도전(s24)과 생각해 보기 질문

| 질문 | 예상 답변 | 대표 오개념과 도움말 |
| --- | --- | --- |
| 포탄이 대포와 같은 쪽으로 날아가는 까닭 | 포탄도 `각도` 값을 읽어서 방향을 정한다 | "포탄이 대포 안에 있어서", "대포가 쏴서". 포탄 스크립트의 `(각도) 도 방향 보기`를 가리키게 한다 |
| 명중 확인이 반복 안에 있어야 하는 까닭 | 날아가는 동안 칸마다 확인해야 지나가는 순간을 잡는다. 밖에 두면 다 날아간 뒤 한 번만 확인한다 | "한 번만 있으면 된다". s18b에서 밖으로 옮겨 쏴 본 결과를 떠올리게 한다 |
| 깃발에서 `발사`를 0으로 정하는 까닭 | 새 게임마다 처음부터 세려고 | "변수는 저절로 0이 된다". 깃발 블록을 빼고 두 번 해 보게 한다 |
| `각도`만 바꾸고 `방향 보기`를 빼면? (q3-4) | `각도` 숫자는 바뀌지만 대포는 그대로이고, 포탄은 바뀐 각도로 날아간다 | "변수를 바꾸면 대포도 바뀐다". 변수는 값만 담고, 움직이는 건 블록이 한다 |
| 위쪽 화살표가 왜 -5인가 (s09) | 위로 들수록 방향 숫자가 0에 가까워져 작아진다 | 수평에서 잰 각도(포수 각도)와 섞음. 포수 각도 = 90 - 스크래치 방향 |
| 1번은 조금 틀려도 맞고 3번은 왜 정확해야 하나 | 멀수록 같은 각도 차이가 크게 벌어진다 | "3번 과녁이 작아서". 세 과녁은 크기가 같다 |
| `y좌표를 -1만큼`만 넣으면 왜 직선인가 (s26) | 칸마다 똑같이 내려가므로 방향만 조금 꺾인 직선이 된다. 떨어지는 양이 점점 커져야 휜다 | "아래로 내리면 휜다" |

### 그 밖의 오개념

- **정하기와 바꾸기 혼동**: `각도를 -5로 정하기`를 쓰면 대포가 한 번에 -5(거의 위)로 간다. s07 실험표로 되짚는다.
- **숨기기와 멈추기 혼동**: 숨기기는 보이는 것만, 멈추기는 실행만 다룬다. 이 게임에서는 멈추기를 빠뜨려도 겉으로 차이가 거의 없다. 숨은 스프라이트는 닿지 않아 명중이 두 번 오르지 않고, 숨은 포탄은 화면을 다시 그리지 않아 남은 반복이 곧바로 끝나기 때문이다(엔진에서 확인). 그래서 "멈추기가 없으면 고장 난다"고 가르치지 않고 "할 일이 끝났으니 멈춘다"고 설명한다.
- **포탄이 대포 끝에서 나온다고 생각함**: `대포로 이동하기`는 대포가 도는 중심(뒤쪽 둥근 부분)으로 간다. 포탄은 대포보다 앞 레이어라 대포 위에 나타났다가 포구 쪽으로 날아간다(시작 프로젝트의 레이어: 과녁 1, 대포 2, 포탄 3).
- **연사**: 포탄이 날아가는 동안 스페이스를 다시 눌러도 스크래치는 그 스크립트를 새로 시작하지 않는다. 그래서 포탄이 사라진 뒤에 쏴야 `발사`가 오른다. 학생이 "왜 안 쏴지냐"고 물으면 이것이다.

### 퀴즈 정답과 의도

퀴즈 스텝마다 3문항만 화면에 남겼다. 틀리면 틀린 문항을 따로 표시하지 않고, 그 문항 아래에 노란 칸으로 힌트를 보여 준다. 통과하면 모든 문항에 해설이 나온다. 뺀 문항은 수업 중에 말로 묻는 질문으로 쓴다.
