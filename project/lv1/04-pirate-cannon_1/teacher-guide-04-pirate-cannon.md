# Lv.1-4 해적선 대포 · 강사용 안내서 (2판)

학생 화면에는 나오지 않는 내용이다. 교안 본문과 퀴즈는 `scratch-lv1/04-pirate-cannon/unit.json`에 있다.

## 학습 목표

1. 스크래치 방향이 위 0, 오른쪽 90, 아래 180이라는 것을 알고, 원하는 쪽을 보는 숫자를 고를 수 있다.
2. 변수를 만들고, `정하기`와 `바꾸기`의 차이를 설명하고, 블록의 숫자 칸에 변수를 넣어 쓸 수 있다.
3. 모든 스프라이트가 쓰는 변수로 두 스프라이트가 값을 나누고 신호를 주고받을 수 있다.
4. 쏘기 전에 각도기로 각도를 어림하고, 같은 각도 차이라도 멀리 갈수록 크게 빗나간다는 것을 말할 수 있다.

## 시간 배분 (120분)

실습 스텝은 대부분 3~6분짜리로 잘게 나눴다. 읽기 부담은 이야기 3스텝에 몰려 있으니 강사가 그림을 보며 함께 읽는다.

| 시간 | 스텝 | 내용 |
| --- | --- | --- |
| 0~10분 | s01~s03 | 이야기(투석기, 천자총통, 1도 오차, 타르탈리아 45도, 블랙비어드), 오늘 만들 게임 |
| 10~22분 | s04, s05, q1 | 방향 블록 예측 놀이, 대포 체조, 방향 퀴즈 |
| 22~32분 | s06, s07, q2 | 변수 만들기, 변수 놀이터(정하기와 바꾸기), 변수 퀴즈 |
| 32~48분 | s08~s11, q3 | 깃발 준비, 위·아래 화살표, 대포가 각도 말하기, 조준 퀴즈 |

| 76~98분 | s18~s22, q5 | 명중 변수, 명중 판정, 과녁 옮기기, 펑 효과, 과녁 3곳, 명중 퀴즈 |

## 퀴즈 형식 (unit.json 안의 퀴즈 스텝)

퀴즈는 `steps` 배열 안에 `"type": "quiz"`인 스텝으로 들어 있다. 실습 스텝과 같은 순서로 스텝 점 하나를 차지한다.

```json
{
  "key": "q3-aim",
  "type": "quiz",
  "title": { "ko": "확인 퀴즈: 조준", "en": "Quiz: aiming" },
  "questions": [
    {
      "id": "q3-1",
      "kind": "code",
      "prompt": { "ko": "...", "en": "..." },
      "blocks": { "ko": "scratchblocks 문법, 빈칸은 (?) 또는 [? v]", "en": "..." },
      "image": "media/....png",
      "options": [ { "ko": "5", "en": "5" }, { "ko": "-5", "en": "-5" } ],
      "answer": 1,
      "explain": { "ko": "...", "en": "..." }
    }
  ]
}
```

| 필드 | 뜻 |
| --- | --- |
| `kind` | `choice`(개념), `code`(블록 일부를 `?`로 가린 빈칸), `predict`(실행 결과 예측). 세 가지 모두 화면은 보기 고르기 |
| `blocks`, `image` | 선택. 문제와 함께 보여 줄 블록 그림이나 이미지 |
| `answer` | `options` 배열의 0부터 시작하는 번호 |
| `explain` | 답을 고른 뒤 보여 줄 해설 |

정답 위치가 한쪽에 몰리지 않도록 생성기가 문항마다 보기 순서를 돌려 두었다.

**기획서에 반영할 것**: 기획서 6장은 "미니퀴즈는 JSON에 넣지 않는다"고 되어 있으므로 이 형식으로 바꿔야 한다. 가져오기 스크립트가 퀴즈 스텝을 기존 `QUIZ` 테이블로 옮기고, 학습 화면이 `code`와 `predict` 문항의 블록 그림을 그리도록 해야 한다. 통과 기준(모든 문항 정답, 다시 풀기 허용)도 함께 정한다.

**사진**: 삽화는 저작권 걱정이 없도록 모두 직접 그렸다. 실제 사진을 넣고 싶다면 다음 검색어로 공개 저작물(퍼블릭 도메인, CC)을 찾아 `media/`의 같은 이름 파일을 바꾸면 된다: 천자총통 유물 사진(국립진주박물관, 국가유산포털), 'gunner's quadrant', 'trebuchet replica', 'Queen Anne's Revenge cannon'.

## 채점 규칙에 관한 메모 (개발자용)

- **변수 이름의 언어별 값**: 기획서 9장은 비교 *값*에 `{"ko", "en"}`을 쓰도록 했다. 이 단원은 변수를 이름으로 찾는 `variableExists`의 `name`과 동적 검사의 `variable` 대상 `name`에도 같은 형식을 썼다. 채점 엔진이 이를 받도록 해야 한다.
- **스페이스 키**: `keyPress`의 `key`는 기획서 예시(`ArrowRight`)에 맞춰 `KeyboardEvent.key` 값으로 적었고, 스페이스는 `" "`이다.
- **스프라이트 이름**: 시작 프로젝트가 이름을 정하므로 `대포`, `포탄`, `목표`를 이름으로 가리켰다. 학생이 이름을 바꾸면 채점이 실패한다(스텝 2에 안내 없음, 수업에서 구두로 안내).
- **과목 키**: 커리큘럼의 Lv.1~3 체계에 맞춰 `subject`를 `scratch-lv1`로 했다. 기획서의 과목 이름(주니어, 기본, 심화)을 바꾸면서 함께 정한다.
- **확장 미션**: 기획서에 선택 스텝이나 강사 확인 스텝이 없어서, 채점 없는 읽기 스텝(s25)으로 넣었다.
- **새로 쓴 채점 기능**: `clickSprite`의 `sprite`(s05), `sayText` 비교(s11), `costume`을 모양 이름으로 비교(s15, s21), `hasBlock`의 `inputs`를 `{"TIMES": {"op": "eq", "value": 40}}` 형태로 비교(s16, s17). 기획서 7장에 이름은 있지만 값의 형식이 정해지지 않은 것들이라 엔진 구현 때 맞춰야 한다.
- **오답으로 시험할 것**: 아래쪽 화살표가 -5인 작품(s10 실패), 포탄이 고정 방향 90을 보는 작품(s12 실패), 만약 블록이 반복 밖에 있는 작품(s19 실패), 불꽃 모양에서 돌아오지 않는 작품(s15 실패).
